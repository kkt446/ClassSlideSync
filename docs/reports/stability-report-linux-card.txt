2. 接口设计
====================================================================
服务只认 ICardSink，不再关心「Win32 分层窗口」还是「Avalonia Window」：

    +----------------------+        +-------------------+        +---------------------+
    | SlideSyncService     |  --->  | ICardSink         |  --->  | NativeOverlayCard   | (Windows)
    |  card / linuxCard    |        | (Ui/ICardSink.cs) |  --->  | LinuxCardWindow     | (Linux)
    +----------------------+        +-------------------+        +---------------------+

- 语义化别名：Show() = Windows 的 Expand()（清抑制 + 20s 预览）；Hide() = Windows 的 HideForAutomation()
  （只收卡片不拆引擎）。Windows 侧用显式接口实现转发，所以重构前后行为逐字节一致。
- 线程约定：接口方法可从任意线程调用；实现自己负责切 UI 线程（Win32 是 PostMessage，Avalonia 是
  Dispatcher.UIThread.Post）。接口注释里写明了「实现不得把异常抛回服务」。
- IsCreated / IsHidden 用于自动化「显示/隐藏悬浮卡片」的判断；Linux 的 IsCreated = Avalonia Window 已 Show。
- HistoryJumpRequested / OpenDeckRequested 在 Linux 上保留但从不触发（历史面板、外部打开器还没做），
  LinuxCardWindow 里用 `#pragma warning disable CS0067` 标注。

Windows 侧的映射（全部落在既有方法上，零语义变化）：
    Show()  -> Expand()
    Hide()  -> HideForAutomation()
    Log     -> 原有 public Action<string> Log 字段（setter 把 null 换成空委托，防止实现方未接日志时 NRE）

3. LinuxCardWindow 设计
====================================================================
3.1 窗口属性（任务指定项，逐条落实）
    SystemDecorations = None
    WindowStartupLocation = Manual
    Topmost = true
    ShowInTaskbar = false
    CanResize = false
    TransparencyLevelHint = new[] { WindowTransparencyLevel.Transparent }
    Background = Brushes.Transparent
    外层 Border：CornerRadius = CardAppearance.Radius（默认 10）、BorderThickness 1（hairline）、
    ClipToBounds = true；背景色为 CardAppearance 的 Bg + BgAlpha（默认 230）带 alpha 的 SolidColorBrush。

3.2 版式（坐标全部是 DIP，取自 Windows 卡片的 96dpi 像素值；Windows 那套本来就是「1 DIP = 1 px @96dpi」）
    W = look.CardWidth（默认 236），H = look.CardHeight（默认 176）
    onRight 时：padL = 14，padR = 28；onLeft 时对调（把手一直在外侧）
    inner = W - padL - padR = 194
    标题：      (padL, 12)，宽 = 齿轮左侧 - padL - 4，高 20，12.5 SemiBold，超长 CharacterEllipsis
    齿轮：      24×24，位于 (W - (onRight?28:14) - 24, 10)，向量绘制（8 齿 + 圆环），点击 → PanelRequested
    大页码：    (padL, 32)，高 54，40 SemiBold，左列宽 max(30, rightX-padL-4)，rightX = padL + 70
    「共 N 页」：(rightX, 34)，宽 rightW，高 20，10.5 常规，muted，右对齐
    「还剩…」： (rightX, 56)，宽 rightW，高 30，11.5 SemiBold，text 色，右对齐，超长省略
    按钮：      (padL, 94)，inner×32，圆角 8；实心 accent 填充 + 白字 12.5 SemiBold
                「从第 N 页接着讲」；无页码时灰底 muted 文案（与 Windows 同文案/同切换条件）
    进度条：    (padL, 134)，inner×4，圆角 2，轨道 #CDD0D5，填充 accent，
                宽 = round(inner × page/total)，页码>0 时最小 2px（与 Windows ProgressFillWidth 同规则）
    底部一行：  (padL, 146)，inner×18，10.5 muted：有历史显示「历史 · N 次 ›」，否则显示状态/页码
    外侧把手：  宽 18、整高，贴外边缘；底色 Mix(bg,text,0.10)，箭头 ❯/❮（14），点击 → Hide()

    与 Windows 的对应常量核对过：CardPadTop 12、TitleStep 20、PageBlockStep 54、BtnGapTop 8、
    BtnHeight 32、BarGapTop 8、BarHeight 4、HistGapTop 8、HistStep 18、CardPadBottom 12，
    合计 12+20+54+8+32+8+4+8+18+12 = 176 = CardAppearance.Resolve 的默认高度。

3.3 DPI / 缩放
    - 全部用 DIP，字号直接取 Windows 那套「96dpi 下的 px 值」（12.5/10.5/11.5/40/14），
      因为 Avalonia 的 FontSize 单位也是 DIP；窗口像素尺寸 = DIP × TopLevel.RenderScaling。
    - 实测：scale=1 → 窗口 236×176；scale=1.5 → 354×264（= 236×1.5 / 176×1.5），
      与任务里 96/144dpi 的 236×176 / 354×264 完全一致（见 shots/linux-card-144-right.png）。
    - 位置计算用「物理像素」：x = 工作区右 - 像素宽，y = 工作区上 + round((工作区高 - 像素高) × v%)，
      像素尺寸 = DIP × RenderScaling，所以 1.5 倍下贴边仍然严丝合缝。

3.4 交互
    - 点按钮 → JumpRequested；点齿轮 → PanelRequested；点把手 → Hide()。
    - 拖动：任意空白处按下不立即 Capture（否则按钮/齿轮的 PointerReleased 会被吞），
      移动超过 4 DIP 才 Capture；拖动中实时 `win.Position = start + delta × scaling`；
      松手 → DropCard()：按窗口中心在屏幕左半/右半决定 onRight，按
      (top - 工作区上) / (工作区高 - 窗高) 算竖直百分比，改 look、重建、重新 Place，然后
      触发 PositionChanged(onRight, percent)。
    - 自动隐藏：DispatcherTimer，5..600s（默认 15s）；Expand()/Show() 会给 20s 预览期；
      新数据到达会重新显示（实测卡片自动隐藏后，页码更新会把它唤回来）。

3.5 线程安全
    - 所有窗口操作都经 Post()（Dispatcher.UIThread.Post）；状态字段 volatile。
    - Diag() 曾被服务在后台线程调用，Avalonia 抛 "Call from invalid thread"；现在 Diag 返回
      UI 线程缓存的 lastDiag 字符串 + volatile 状态位，任意线程安全（这个坑已修掉，最终日志里没有该异常）。

3.6 外部状态驱动（任务第 4 条）
    `ApplyExternal(deckName, page, total, isShowing)`：
    - deck=课件名（服务已用 Path.GetFileNameWithoutExtension 去扩展名）
    - page/total 直接来自 LinuxSlideSource.TryReadDetailed
    - isShowing 决定按钮文案与「等待放映 / 正在识别」的兜底
    - 剩余页 = total - page；剩余分钟暂按 1.5 分钟/页估算（代码里标了 TODO，等 Ledger 的页速）
    - 历史次数固定 0（Linux 还没有台账面板），所以底部显示页码行而不是「历史 · N 次」

服务侧数据流（每 500ms，同事写的桥 + 我的卡片）：
    current.json ──(LinuxSlideSource.TryReadDetailed)──> LinuxTick ──> PublishLinuxPage
        ──> LinuxPageChanged ──> OnLinuxPageChanged ──> PushLinuxPage ──> ApplyExternal
    （页码没变就不推；文件消失/过期 10s/坏 JSON → 推 Empty → 卡片回「无页码」并自动隐藏）

   "Resource temporarily unavailable"，`xwd -root`/`xwd -id` 报 BadMatch，机器上也没有 grim/scrot/ffmpeg。
   所以只有窗口级截图（import -window <id>），没有「卡片贴在桌面右侧」的整屏图。
2) 拖动位置没有落盘到 SyncSettings.json：Plugin.cs 的非 Windows 分支（同事所写，50-92 行）
   没有像 Windows 分支（107-110 行）那样订阅 Settings.PropertyChanged → ConfigureFileHelper.SaveConfig。
   服务里 OnPositionChanged 已把 CardOnLeft/CardVerticalPercent 写进内存 settings，
   但重启后仍读文件里的旧值（实测拖到 37% 后文件里还是 50）。
   建议在 Linux 分支补 3 行保存钩子；这次没改，避免和正在改 Plugin.cs 的同事冲突。
3) 页码源只读：按钮点击只显示「Linux 版暂不支持跳页（页码来自只读适配器）」；
   历史面板、打开课件、页速/剩余分钟的真实估算都没有（剩余分钟目前按 1.5 分钟/页估，代码里 TODO）。
4) 收起态「把手/药丸」没做：Linux 卡片只有展开态，点外侧把手是隐藏而不是缩成窄条。
   （任务接口里只有 Show/Hide/Expand，没有要求 pill，但和 Windows 的视觉行为有差别。）
5) 控制面板（ControlPanel）是普通 Avalonia 窗口，打开后可能盖住卡片：
   实测先开面板再点卡片按钮时，点击被面板吃掉；关掉面板后按钮正常。
   后续可让面板不抢置顶，或卡片点击时先激活自己。
6) 自动化（Automation/Action/Trigger）仍只在 Windows 注册；Linux 上「显示/隐藏悬浮卡片」
   这类动作暂时不可用（Plugin.cs 非 Windows 分支直接 return）。
7) Linux 设置页文案还是「本插件依赖 Windows 的窗口与 COM 自动化，当前平台不可用。」
   （Views/SettingsPages/PlatformUnavailablePage.cs），现在已经不准确了，但不在这次范围内，没改。
8) 只在 WSL 的 xrdp/XWayland 环境验证过，没在真机 GNOME/KDE Wayland 或纯 Xorg 桌面上跑；
   多显示器、混合 DPI（每屏不同缩放）没测（Place() 用 ScreenFromWindow 取当前屏，理论上支持）。
9) 未在 Linux 上验证「自动隐藏 15s / 预览 20s」的完整时序边界（只看到 auto-hidden 与重新显示）。
