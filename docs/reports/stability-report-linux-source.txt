2. JSON 协议
------------
2.1 路径
  默认：
    ~/.local/share/classslidesync/current.json
  等价实现：
    Environment.GetFolderPath(SpecialFolder.LocalApplicationData)/classslidesync/current.json
    在 Linux 上 .NET 会尊重 $XDG_DATA_HOME；无条件时是 ~/.local/share。
  适配器也尊重 --out 与 $XDG_DATA_HOME，便于隔离排障。

2.2 内容
  {
    "file": "/home/teacher/课件/第3节.pptx",
    "page": 4,
    "total": 10,
    "showing": true,
    "updated": "2026-10-31T07:00:00Z",
    "app": "libreoffice"
  }

  字段      类型     含义
  file      string   课件绝对路径（LibreOffice 端把 file:///... 转成系统路径并 unquote）
  page      int      当前页，从 1 开始；0 表示还没拿到
  total     int      总页数
  showing   bool     true=正在全屏放映；false=只是打开了文档/编辑态
  updated   string   UTC 时间，ISO-8601（Z 结尾）；心跳字段
  app       string   libreoffice 或 wps

2.3 过期与容错
  - updated 超过 10 秒（StaleSeconds）→ TryRead 返回 false，日志
    「bridge: 数据过期 N 秒（路径）」。
  - updated 缺失/不可解析 → 同样按过期处理。
  - 未来时间超过 60 秒只记「请检查系统时间」，不当成过期。
  - 文件不存在、空文件、坏 JSON、缺 file、page/total 为负、IO 异常 → false + 日志，
    绝不抛。
  - 插件每 500ms 读一次；同一页的重复读不重复写 app.log，只有换文件/换页/
    放映态变化/数据中断才记一行。
  - 适配器停止写后，最多 10 秒卡片回到「无页码」。

2.4 写入原子性
  - LibreOffice 适配器：临时文件 + fsync + os.replace，插件不会读到半截 JSON。
  - WPS 适配器：wps.FileSystem 没有 rename，writeFileString 直接覆盖；极端情况下
    可能读到半截，LinuxSlideSource 会丢弃这一拍并在 500ms 后重试。

3. LibreOffice Impress 适配器：安装与运行
-----------------------------------------
3.1 安装（Ubuntu/Debian）
  sudo apt update
  sudo apt install -y libreoffice-impress python3-uno
  /usr/bin/python3 -c "import uno; print('uno ok')"

  注意：unoconv 是文档转换工具，不提供实时页码，不是本适配器的依赖；
  本次 WSL 验证镜像里装了它，但适配器没有调用。

3.2 让 LibreOffice 带 UNO socket 启动
  --accept 只在启动时生效；已经在运行的实例不会因为再执行一次命令就开端口。
  推荐先退出，再一条命令打开课件并监听：

    pkill -f soffice || true
    soffice --impress \
      --accept="socket,host=127.0.0.1,port=2002;urp;" \
      "/home/teacher/课件/第3节.pptx"

  不想和日常实例抢配置时用独立 profile：

    soffice --impress \
      -env:UserInstallation=file:///tmp/lo-slidesync-profile \
      --accept="socket,host=127.0.0.1,port=2002;urp;" \
      "/home/teacher/课件/第3节.pptx"

  验证端口：
    ss -ltnp | grep 2002

  为什么写 127.0.0.1：LibreOffice 只监听 IPv4；部分系统把 localhost 先解析成 ::1，
  适配器会报 Connection refused。--accept 和适配器两边都用 127.0.0.1 最稳。

3.3 启动适配器
  cd tools/linux-adapters/libreoffice
  ./run.sh
  # 或
  /usr/bin/python3 slidesync_lo.py

  常用：
    ./run.sh --port 2003
    ./run.sh --interval 0.5
    ./run.sh --out /tmp/current.json
    ./run.sh --once
    ./run.sh --quiet

  --once 最适合排障：读一次、打印 JSON、退出。返回码 0=成功，3=连上了但没有演示文档。

3.4 行为
  - 每秒轮询；放映态用 XPresentation2.isRunning() 判断；当前页优先
    XSlideShowController.getCurrentSlideIndex()+1。
  - 编辑态也写，showing=false，page 是当前编辑页。
  - 没有演示文档时不写新文件，让 updated 自然过期。
  - LibreOffice 退出/重启后每 2 秒重连，不需要重启适配器。

4. WPS Linux 适配器：安装与运行
-------------------------------
4.1 安装
  mkdir -p ~/.local/share/Kingsoft/wps/jsaddons/ClassSlideSync
  cp main.js ribbon.xml ~/.local/share/Kingsoft/wps/jsaddons/ClassSlideSync/

  然后在 jsaddons 根目录（不是 ClassSlideSync/ 里面）放 publish.xml：

    cp publish.xml.example ~/.local/share/Kingsoft/wps/jsaddons/publish.xml
    # 编辑 publish.xml，把 /home/teacher 换成实际家目录

  示例：
    <?xml version="1.0" encoding="UTF-8"?>
    <jsplugins>
      <jspluginonline enable="enable_dev"
                      type="wpp"
                      name="ClassSlideSync"
                      url="file:///home/teacher/.local/share/Kingsoft/wps/jsaddons/ClassSlideSync/" />
    </jsplugins>

  type="wpp" 只加载到 WPS 演示进程；url 必须指向目录且以 / 结尾。
  部分版本用 jsplugins.xml，优先 publish.xml，具体见 wps/README.md。

  完全退出 WPS 再启动，打开 10 页 .pptx，进入放映、翻到第 4 页：

5.6 一个环境干扰（如实记录）
  验证期间，默认路径 ~/.local/share/classslidesync/current.json 被另一个进程
  周期性覆盖，内容为：
    {"file":"/root/课件/浮层卡片测试.pptx","page":13,"total":18,"showing":true,...}
  约每 12 秒刷新一次；ps 里看不到对应进程，疑似同事/宿主侧通过 \\wsl$ 写同一路径。
  为了避免把别人的数据误判成自己的测试结果，最终验证改用：
    --out /tmp/classslidesync-verify/classslidesync/current.json
    XDG_DATA_HOME=/tmp/classslidesync-verify
  上面 5.4 的所有结果都来自这个隔离目录。默认路径本身也仍可用，只是会被外部写入者
  覆盖；如果现场出现「页码不是自己课件的」，先检查是否有第二个适配器在写同一个文件。

5.7 失败的尝试（供排障）
  - 第一次 soffice 启动约 12 秒后崩溃：/tmp/soffice.log 末尾
    「Unspecified Application Error」「Fatal exception: Signal 6」「X IO Error」。
    原因是 Xvfb/显示环境不稳；重建 Xvfb + 新 profile 后稳定。
  - 用 localhost 连 2002 报 Connection refused，ss 显示 127.0.0.1:2002 在听；
    改用 127.0.0.1 解决（已写进两个 README）。
  - LibreOffice 残留锁文件导致 loadComponentFromURL 卡在「locked for editing」
    对话框；清理 .~lock.* 并换 profile 解决。
  - pyuno 没有 uno.queryInterface；要用 pres.queryInterface(uno.getTypeByName(...))。
  - XSlideShowController.gotoSlide 的参数是 XDrawPage，不是页码；必须传
    doc.getDrawPages().getByIndex(3)。

1) WPS Linux 整条路径未实测（没有 WPS Linux 环境）。main.js、ribbon.xml、
   publish.xml 的 API 名称、加载项目录、注册字段都只是按公开文档写的。
   这是本任务最大的未验证项。
2) 没有在真实 ClassIsland Linux 宿主进程里启动插件并观察 LinuxCardWindow 的
   实际显示。已做的是：LinuxSlideSource 独立探针 + 服务 500ms 读文件逻辑的编译
   与代码路径检查；卡片 UI 的最终观感需要同事在 UbuntuCi 的 /root/ci-linux 里
   实际跑一次。ClassIsland 宿主本身未在本次验证中重启。
3) Xvfb 下放映截图是黑屏，没有「第 4 页画面」的视觉截图；页码正确性由
   UNO 的 getCurrentSlideIndex 日志和 JSON 证明。
4) WPS 适配器写文件不是原子的（没有 rename），极端情况下可能闪一帧无页码；
   已文档化。
5) 适配器只能连「启动时带 --accept」的 LibreOffice 实例；老师双击打开的实例
   没有 socket，需要统一用带 --accept 的启动方式。
6) 默认 current.json 可能被多个适配器/测试同时写；生产环境应保证只有一个写者。
7) WPS 侧没有做 node --check（WSL 未装 node）；XML 已用 Python ElementTree
   解析通过。
