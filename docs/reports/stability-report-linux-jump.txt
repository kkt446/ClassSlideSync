三、command.json 协议
----------------------

路径：$XDG_DATA_HOME/classslidesync/command.json，默认 ~/.local/share/classslidesync/command.json
（和 current.json、README.txt 同目录；目录不存在时插件会建）

内容（一行 JSON，UTF-8 无 BOM）：

    {"page":3,"ts":"2026-10-31T08:44:21.745Z"}

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| page | int | 目标页，**从 1 开始**；1..total 之外适配器拒绝执行 |
| ts | string | 插件写入时刻，UTC ISO-8601，带毫秒和 Z；适配器按它去重、判过期 |

写入方式（插件侧，Core/LinuxSlideSource.cs:233-261）：
    写临时文件 command.json.tmp.<guid> → File.Move(tmp, command.json, overwrite:true)
    → 适配器任何时刻读到的都是完整文件，不会读到半个 JSON。
    page<=0 直接拒绝；目录只读/磁盘满等写失败 → 返回 false + 原因，宿主只记日志，不影响上课。

消费方式（适配器侧，slidesync_lo.py:383-430）：
    1. 每轮轮询读 command.json；
    2. (page, ts) 与本进程上次处理的相同 → 跳过（同一条命令只执行一次，跨重连也记得）；
    3. ts 超过 120 秒 → 当成历史遗留，记 `command: ignore stale jump to N (X s old)`，不执行；
    4. page 越界 → `command: jump to N -> fail (page out of range 1..total)`；
    5. 放映中 gotoSlide(XDrawPage)，编辑视图 setCurrentPage(XDrawPage)；
    6. 成功后**立刻**重读页码并重写 current.json（刷新 updated，避免卡片以为数据过期）；
    7. 日志 `command: jump to N -> ok`；异常 `command: jump to N -> fail (异常: 消息)`，异常不外抛。

配套的 current.json（适配器 → 插件，只读）不变：file/page/total/showing/updated/app，10 秒过期。
两个文件互不依赖：没有 command.json 插件照常工作；没有适配器时插件写命令只会留下文件。

六、没做到的地方 / 已知限制
---------------------------

1) WPS 适配器跳页未实测。
   tools/linux-adapters/wps/main.js 已按 PowerPoint 兼容对象模型加了 command.json 轮询
   （View.GotoSlide(page)，1 起），但这台机器 Windows 侧和 WSL 侧都没有 node，也没有可用的
   WPS Linux 环境，只做了人工审查；README 里已标注「跳页未实测」。
   LibreOffice 那条路是实测过的。

2) 适配器重启会重放最后一条命令（2 分钟内）。
   去重状态在进程内存里（last_command_tag），进程重启后不落盘；只要 command.json 还在、
   ts 不超过 120 秒，重启后的第一轮会再执行一次同样的跳页。对同一页来说是幂等的，
   但如果老师重启适配器前手动翻到了别页，会被拉回命令里的那一页。取舍：不做落盘状态，
   避免多一个需要清理的文件；120 秒窗口已经限制了影响面。

3) 只能跳「当前放映的那份课件」。
   Linux 适配器只认当前窗口里的演示文稿，换课件得老师自己打开；指定别份课件时插件直接拒绝
   （日志「linux jump: 拒绝跨课件跳页 a.pptx -> b.pptx」，卡片提示「Linux 上只能跳当前放映的课件」）。

4) 卡片自动隐藏后，页码变化不会自动把它弹回来（既有行为，本次未改）。
   Hide() 之后 RenderNow() 只在 showOnStart && hasData && !hidden 时才 ShowWindow。
   实测时为了在卡片还可见的窗口内点击，把 WSL 宿主里的 AutoHideSeconds 临时改成 600，
   验证完已改回 15。

5) XWayland 下卡片是否置顶取决于窗口管理器。
   卡片自己设了 Topmost=true（Ui/LinuxCardWindow.cs:303、737），正常 GNOME/KDE 上应在全屏放映之上；
   但在本次 WSL 的 Weston/XWayland 里，LibreOffice 全屏放映窗口有时压在卡片上，
   合成点击会落到放映窗口（观测到幻灯片被点成下一页）。最终验证时先结束/移开放映窗口再点卡片。
   这是测试环境的图层问题，不是插件逻辑问题，但说明「真机上卡片必须真的在最上层」这一点需要
   在目标桌面环境里再确认一次。

6) 宿主被 SIGKILL 会留下 .disabled，下次启动插件不加载。
   本次排障时遇到：kill -9 之后 /root/ci-linux/data/Plugins/ClassSlideSync.Plugin/.disabled
   被宿主写下，重启日志变成「此次会话没有加载插件。」；删掉 .disabled 后正常加载。
   正常 SIGTERM 退出不会产生。这是 ClassIsland 的 AutoDisableCorruptPlugins 行为，不是插件 bug。

7) 没有做的事（按要求）：没动 Ui/NativeOverlayCard.cs，没动 Core/SessionEngine.cs 的 Windows 逻辑，
   没启动 Windows 上的 ClassIsland/WPS，没部署到 C:\Users\xzq\Desktop\github\ClassSlideSync\classisland\...，
   没做任何 git 操作（该目录本身也不是 git 仓库）。
