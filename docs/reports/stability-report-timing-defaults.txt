2. 任务A：时机判定
--------------------------------------------------------------------------------
2.1 三档与默认值
      LessonStart = 0  「上课开始时」        默认，等于 1.2.2 之前的行为（正课一开始就打开）
      BeforeClass = 1  「上课前 N 分钟」     N = BeforeClassOpenMinutes，默认 2，范围 0–30
      AfterClass  = 2  「下课后 N 分钟」     N = AfterClassOpenMinutes，默认 2，范围 0–30
    N 的两个数字框用 IsVisible 绑 ShowBeforeClassOpenMinutes / ShowAfterClassOpenMinutes，
    即「总开关打开 且 处于对应档位」才可见、可编辑；两个界面同一套规则。

2.2 判定伪代码（Core\SyncSettings.cs 的 SubjectFolderTiming.Evaluate）
    输入：moment（档位）、now（当前时刻，由调用方传入，函数自己不读系统时间）、
          periods（今天的课表，只含 TimeType==0 的上课项）、n（分钟数，已夹到 0–30）
    对每一节课 p（第几节 + 起止时间）：
        LessonStart : p.Start <= now <= p.End
        BeforeClass : n > 0 → p.Start - n分钟 <= now <  p.Start        （左闭右开）
                      n = 0 → p.Start         <= now <  p.Start + 1分钟（退化成"打铃那一刻"）
        AfterClass  : n > 0 → p.End < now <= p.End + n分钟             （左开右闭）
                      n = 0 → p.End < now <= p.End + 1分钟
        命中就返回 { Hit=true, Period, Key="日期|start/before/after|第几节|HH:MM-HH:MM",
                     Reason="上课前 2 分钟 · 第3节 09:40 开始" 这样的中文说明 }
    都不命中 → { Hit=false, Key="", Reason="" }

    为什么窗口一边开一边闭：相邻两节之间只有几分钟时，"上一节的下课窗口"和"下一节的课前窗口"
    可能在时间上重叠；左闭右开/左开右闭保证同一时刻只落在一个窗口里，去重键也不会互相顶掉。

2.3 心跳里怎么用（Services\SlideSyncService.cs）
    每拍（Timer 间隔 2000ms，见第 5 节）：
        if (档位 == 上课开始时)  { 原来的 if (inClass && lessonKey 变了) { lastLessonKey = …; TryOpenSubjectFolder(); } }
        else                     { TickSubjectFolderMoment(); }

        TickSubjectFolderMoment():
            if (!AutoOpenSubjectFolder) return;             // 总开关
            periods = ReadLessonPeriods();                  // 课表：TimeType == 0
            if (periods.Count == 0) return;                 // 今天没排课 / 读不到
            hit = SubjectFolderTiming.Evaluate(档位, DateTime.Now, periods, 课前N, 课后N);
            if (!ShouldFire(subjectFolderMomentKey, hit)) return;   // 键相同 = 这节已经开过
            subjectFolderMomentKey = hit.Key;               // 先记账再开门（开门失败也不反复重试）
            科目 = (档位 == 下课后) ? lastClassSubject     // 课间 CurrentSubject 是"课间"，只能用上课时记下的
                                     : NextSubjectName();    // 课前用课表的下一节
            log("subject folder timing: " + hit.Reason + (" · " + 科目 或 " · 科目名未知"));
            TryOpenSubjectFolder(科目);                     // 真正打开（宿主 IUriNavigationService 优先）

    同一节课只触发一次：键 = 日期 + 档位 + 第几节 + 起止时间。
      * 窗口里心跳会打十几拍，只有第一拍 ShouldFire 为 true；
      * 键里带日期，第二天同一节课照样能开；
      * 默认档保持原来的 lastLessonKey 一套，不去动它。

    实际会写进 app.log 的两种时机日志行样例（前缀是 ledger.Log 加的时间戳）：
      subject folder timing: 上课前 2 分钟 · 第3节 09:40 开始 · 数学
      subject folder timing: 下课后 2 分钟 · 第3节 09:40 下课 · 数学
      （上课开始时那一档沿用老日志：subject folder: opened D:\课件\数学 for 数学）


3. 任务B：默认值在界面上可见
--------------------------------------------------------------------------------
3.1 滑条：默认值刻度
    结构（两个界面一样，16 处）：
        <Grid VerticalAlignment="Center">
            <Slider x:Name="AutoHideSecondsSlider" Width="170" Minimum="5" Maximum="120" ... />
            <Border Width="2" Height="10" HorizontalAlignment="Left" VerticalAlignment="Center"
                    IsHitTestVisible="False"
                    Background="{DynamicResource AccentTextFillColorPrimaryBrush}"
                    Margin="{Binding Bounds.Width, ElementName=AutoHideSecondsSlider,
                                     Converter={StaticResource DefaultMark},
                                     ConverterParameter='5,120,15'}" />
        </Grid>
    位置换算（Core\SyncSettings.cs:1189 DefaultMarkGeometry.Offset）：
        百分比     = (默认值 - 最小) / (最大 - 最小)        // 夹到 0–1
        可走长度   = 滑条宽度 - 2 × 10px                    // Fluent 拇指约 20px 宽，两端各让 10
        左边距     = 10 + 百分比 × 可走长度 - 2/2            // 再夹到 [0, 宽度-2]
    为什么这样：宽度来自绑定的 Bounds.Width（随窗口缩放实时变），最小/最大/默认值来自
    ConverterParameter，所以换宽度、改范围都不会偏。宽度还是 0（还没布局）时返回 0，
    不会出现负边距或越界。刻度 2px、IsHitTestVisible=False，点它等于点滑条，不挡拖拽。
    例子（宽度 180、范围 20–100、默认 90）：10 + 0.875 × 160 - 1 = 149。

5. 未实现项与需要说明的地方
--------------------------------------------------------------------------------
5.1 「收到通知时」这一档：**没做，ClassIsland 2.1 未暴露该事件**
    在 ClassIsland.Core / ClassIsland.Shared 2.1.0.1（本插件引的 PluginSdk 2.1.0.1）里查过：
      * ILessonsService 的公开事件只有 PreMainTimerTicked、PostMainTimerTicked、OnClass、
        OnBreakingTime、OnAfterSchool、CurrentTimeStateChanged —— 没有任何"收到通知/收到广播"事件。
      * INotificationHostService 里和"发通知"有关的方法（ShowNotification / ShowNotificationAsync 等）
        全是 internal；公开的只有 RegisterNotificationProvider / GetNotificationProviderSettings /
        RegisterNotificationConsumer / PullNotificationRequests —— 是"提醒 UI 去拉"的模型，
        不是"收到通知时给我回调"。
      * Core 2.1.0.1 里全部公开事件（NotificationRequest.Canceled/Completed、
        IPluginMarketService.RestartRequested、IRulesetService.ForegroundWindowChanged/StatusUpdated、
        ISplashService.ProgressChanged/SplashEnded、IThemeService.ThemeUpdated、
        ITutorialService.TutorialStateChanged、IWindowRuleService.ForegroundWindowChanged、
        IXamlThemeService.RestartRequested）里也没有通知/广播类的。
    结论：按用户要求"找不到就不要硬造"，保持三档。将来 SDK 暴露了通知事件，只需在
    SubjectFolderMoment 枚举加一档 + SubjectFolderTiming.Evaluate 加一个分支 + 一处订阅。

5.2 心跳不是 50ms，是 2000ms
    任务书写的是"已有的 50ms 定时心跳（ScheduleTick）"，但仓库里 ScheduleTick 的实际间隔是
    2000ms（Services\SlideSyncService.cs:160 `new System.Threading.Timer(ScheduleTick, null, 300, 2000)`；
    全仓没有 50ms 的定时器）。判定就放在这个已有心跳里，所以：
      * 触发时刻与课表时刻的误差 ≤ 2 秒（对"提前 2 分钟"这种粒度足够）；
      * 没有为了这次改动去改心跳频率，避免影响别的功能（也没必要：判定是纯计算）。
    如果以后要求秒级准点，把这一处间隔调小即可，判定函数不用改。

5.3 默认档不受 AutoStartBeforeClass 影响
    「上课开始时」这一档仍走原来的 inClass/lessonKey 判定；课前/课后两档用课表时间与当前时间判定，
    不依赖 AutoStartBeforeClass（那是"卡片要不要提前待命"的开关）。三者互不干扰。
    总开关 AutoOpenSubjectFolder=false 时，三档都不会打开任何文件夹（判定入口先 return）。

5.4 其它
    * 科目名：课前用课表里的下一节（NextClassSubject），下课后用上课时记下的 lastClassSubject
      —— 因为课间里 ILessonsService.CurrentSubject 是"课间"，直接取会拿到"课间"三个字。
    * 找不到对应科目的文件夹时，沿用原来的行为（记 subject folder: no folder for …，不弹任何窗）。
    * 打开失败只记一行日志，不重试（去重键已经记下，避免每 2 秒刷屏）。
