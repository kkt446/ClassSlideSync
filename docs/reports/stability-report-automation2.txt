设置保存/加载机制（ClassIsland 2.1.0.1，Cecil 反射确认）：
- 行动继承 ActionBase<TSettings> 后，ActionItem.Settings（JsonElement）由 ActionBase.GetInstance 用 System.Text.Json
  反序列化成 TSettings，再 set_SettingsInternal；行动与设置控件共享同一个 settings 实例。
- 只调用 AddAction<TAction>() 时没有设置控件；必须用 AddAction<TAction, TSettingsControl>()，它会在同一个
  ActionInfo.Id 下再注册 keyed ActionSettingsControlBase，ClassIsland 打开设置抽屉时按 Id 取控件。
- 这是旧版「没法自定义发啥」的根因：旧 NotifyAction 只有普通 CLR 属性 Title/Message，既没有 TSettings，
  也没有注册设置控件。

内建 classisland.showNotification 的形状（Cecil + Default.json.bak 对照）：
- 行动：ClassIsland 内建 NotificationAction : ActionBase<NotificationActionSettings>；
- 设置控件：ClassIsland.Controls.ActionSettingsControls.NotificationActionSettingsControl :
  ActionSettingsControlBase<NotificationActionSettings>，由 AddAction<TAction, TSettingsControl> 注册；
- Default.json 里它的 Settings 字段：Content、Mask、IsContentSpeechEnabled、IsMaskSpeechEnabled、
  IsAdvancedSettingsEnabled、IsSoundEffectEnabled、IsTopmostEnabled、CustomSoundEffectPath、IsEffectEnabled、
  MaskDurationSeconds=5、ContentDurationSeconds=10、IsWaitForCompleteEnabled、IsActive。
- 我们的映射：Mask→Mask、Content→Content、IsTopmostEnabled→IsTopmostEnabled；
  内建把标题/正文的停留时长拆成两个字段，我们按用户要求合成一个 DurationSeconds（默认 10，与内建的
  ContentDurationSeconds 对齐）；语音、音效、等待完成等字段本期不做，避免引入音频/语音依赖。
- 没有直接复用内建 NotificationAction / INotificationHostService：那需要注册 notification provider 与 channel，
  并受系统 Toast 开关影响；本项目已有 ToastNotifier/TrayNotifier 两条可用通道，复用它们风险更低。

四、实现要点与安全边界
----------------------
1. 占位符：
   - {deck}：Path.GetFileNameWithoutExtension(record.FilePath)；
   - {page}：record.EndSlide（>0 才输出，否则空串）；
   - {total}：record.SlideCount（>0 才输出）；
   - {remaining}：max(0, total - page)，仅当两者都有效；
   - 大小写不敏感；未知占位符原样保留；record 为 null 时四个占位符全部替换为空串，不抛异常。
   - 数据源：当前放映课件路径对应的 Ledger.Last(path)；没有则 Ledger.Newest()；再没有则 null。
2. 通知：
   - 置顶勾选：ToastNotifier.Show（操作中心横幅）优先，失败回退 TrayNotifier.Show；
   - 未勾选：TrayNotifier.Show（托盘气泡）优先，失败回退 Toast；
   - 两路都失败只写日志，不影响自动化主流程。
3. 跳到指定页：只调 service.RequestJump(page)（Services\SlideSyncService.cs:982-985 → 私有 RequestJump(null, slide)），
   后者只写 pending（filePath 为空时归一化成 ""），不会启动 PowerPoint/WPS，符合「不启动被控应用」铁律。
4. 打开课件所在文件夹：Service 没有公开的「打开文件夹」方法，且 Services\SlideSyncService.cs 在禁改清单；
   因此在新行动里复制其 944-976 的两步实现（IUriNavigationService.Navigate → Process.Start 回退），没有改服务文件。
5. 清除记录：只调 Ledger.RemoveMany(new[]{ path })，只删台账记录、不删课件文件；RemoveMany 内部自带 try/catch 且会写
   "history: removed N record(s) by hand"。
6. 空服务/空数据：所有 OnInvoke 先 TryService()，null 时写日志后 return；最外层再 try/catch，绝不把异常抛给宿主。
7. 没动禁止文件：Ui\NativeOverlayCard.cs、Ui\ControlPanel.axaml*、Core\SessionEngine.cs、Core\PptBridge.cs、
   Core\SeewoBridge.cs、Views\SettingsPages\*、Services\SlideSyncService.cs 均未修改。
