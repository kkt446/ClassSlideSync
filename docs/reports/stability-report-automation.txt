四、实现说明（行为 + 为什么这么做）
----------------------------------------------------------------
4.1 行动一：打开上次未讲完的课件
  - 只在台账里挑「未讲完 + 不超过 21 天 + 磁盘上确实存在 + 不是「希沃:xxx」伪键」的最新
    一条（Automation\UnfinishedDecks.cs:61 NewestUnfinished）。条件必须和规则用同一把尺子，
    否则会出现“规则说成立、行动却找不到文件”。
  - 打开用 Process.Start(new ProcessStartInfo(path) { UseShellExecute = true })
    （Automation\Actions.cs:62）：让系统默认程序决定是 PowerPoint 还是 WPS，插件不去猜。
  - 打开后不立刻调 COM（套件还没加载完），而是把「待跳页」交给 PendingJump
    （Automation\Actions.cs:73），后台每秒看一次引擎快照的 FilePath，认出来就调
    engine.RequestJumpTo(path, endSlide)（Automation\Actions.cs:162）。后者和卡片按钮、
    控制面板走同一条路径：只抬标志，真正的 COM 跳页仍由 SessionEngine 工作线程执行。
  - 等待上限 120 秒（Automation\Actions.cs:121/148）；重复触发时取消上一次等待，避免
    “连点两次，第二次被旧页覆盖”。
  - OnInvoke 里用 Task.Run 起后台任务后立刻返回（Automation\Actions.cs:34）：打开 PPT 可能
    几秒到几十秒，行动若在这里 await，同一套自动化里排在后面的行动会被一起卡住。
  - 服务拿不到、台账为空、文件被移走、Process.Start 失败：全部只写台账日志，不抛。

4.2 行动二：显示 / 隐藏悬浮卡片
  - 做成一条“切换”行动（用户需求原文就是「让悬浮卡片显示 / 隐藏」）：已待命 → 隐藏，
    否则 → 显示。理由：老师用它的动机只有“现在别挡着/现在要用”，当前 armed 状态就是
    唯一需要的信息，不必在设置里再选一次。
  - 判断在行动层（Automation\Actions.cs:107），真正动作调服务新增的最小公开方法：
    ShowCardForAutomation / HideCardForAutomation（Services\SlideSyncService.cs:970/988）。
    这两个方法只是把调用切回 UI 线程（AutomationOnUi，见 :1010），然后走既有的 Arm/Disarm
    和 card.Expand()——没有复制第二套引擎/卡片逻辑。
  - 全部包在 try/catch 里：自动化里抛异常会打断整套行动，而且老师看不到堆栈。

4.3 规则：上次课件没讲完
  - 语义（按用户原话）：取**全库最近一条记录**，要求 SlideCount > 0 && EndSlide < SlideCount，
    且这条记录不超过 21 天。
  - 为什么不是“最近一条未讲完的记录是否存在”：如果上节课已讲完、再上一节没讲完，后者会
    错误地让规则成立，老师看到“明明讲完了，自动化还说没讲完”。
  - 时间口径：有 EndedAt 用 EndedAt，否则 StartedAt（Automation\UnfinishedDecks.cs:34），
    与 Ledger.Prune 的保留期口径一致；now - last <= 21 天（:45），时间往后偏不算过期。
  - 拿不到服务 / 台账为空 / 解析失败：返回 false，不抛（规则是查询不是命令）。
  - 行动与规则共用 UnfinishedDecks（:24 IsUnfinished / :45 IsFresh / :61 NewestUnfinished），
    避免两边判定漂移。

4.4 改动边界
  - 只新增 Automation\ 三个文件；Plugin.cs 只加 using 和 3 行注册；Services\SlideSyncService.cs
    只在文件末尾追加（961-1022 行），既有代码一行未重排、未改写。
  - 未改 Ui\NativeOverlayCard.cs、Ui\ControlPanel.*、Core\SessionEngine.cs。

七、没验证的部分（真机没启动）
----------------------------------------------------------------
1. 没启动 ClassIsland，所以以下只有“注册器代码路径 + 独立进程实测”，没有宿主 UI 实测：
   - 两条行动在「添加行动」菜单里是否真的出现、图标字形是否好看；
   - keyed transient 实例化后 OnInvoke 在真实自动化线程上的行为；
   - 规则在规则集编辑器里的显示名/图标、StatusUpdated 后多久重新求值。
2. 没启动 PowerPoint / WPS：Process.Start 后“识别到文件 → RequestJumpTo → 真正跳页”
   这条链只验证到“抬标志”，COM 跳页与 120 秒超时后的日志没在真机跑过。
3. 未待命时触发行动一：仍然会打开文件，但引擎不存在，要等调度器进入待命（上课前 1 分钟）
   后才可能跳页；超过 120 秒则放弃（日志会记）。这是刻意取舍，避免行动自己拉起一套引擎。
4. 规则在服务未启动（AppStarted 之前）时返回 false；宿主启动早期若规则被求值，会短暂为假。
5. 并发：连续触发行动一会取消上一次等待；行动二的状态读取不是原子的，两次同时切换可能
   都执行同一个方向（概率极低，没有加锁）。
6. 台账写入依赖既有的 Ledger.Save（引擎侧），自动化只读；没验证台账文件被外部程序占用/
   损坏时的表现（既有 Load 已有损坏备份逻辑，但自动化路径没专门造这个用例）。
7. 没测非中文系统区域设置/夏令时；记录时间按本地时间、InvariantCulture 解析，与既有
   Ledger 一致。
8. 没做“恢复（Revert）”：两条行动都不重写 OnRevert，ActionInfo 的 IsRevertable 会是 false，
   自动化里不会出现“撤销”项——这是预期的（打开课件/切换卡片都不适合自动回滚）。
