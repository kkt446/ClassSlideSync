BUG-01 PendingJump 轮询的线程生命周期（句柄泄漏 + 假日志 + 取消后仍可能跳页）
  现象：每触发一次「打开上次未讲完的课件」，进程就多留一个 CancellationTokenSource；
        连续触发时，被顶掉的那次仍会在 app.log 里写“等了 120 秒没识别到…放弃跳页”，
        日志与事实相反；极端时序下被顶掉的任务还能在取消后多跳一次页。
  根因：Automation\Actions.cs:198-297（PendingJump）
        · Arm 里 `current?.Cancel()` 之后从不 Dispose 旧 CTS（Actions.cs:219），
          而 Watch 用了 token.WaitHandle（惰性分配内核事件），每个 CTS 都带一个句柄
          → 每次触发泄漏一个内核句柄，长期上课会累积。
        · Watch 只在循环头检查 token（Actions.cs:238），RequestJumpTo（Actions.cs:253）
          之前不复查，取消与跳页之间是一个可被踩进去的窗口。
        · 循环退出后无条件写超时日志（Actions.cs:267-272），分不清“超时”与“被新的请求顶掉”。
        · 任务收尾后 current 不清空，字段一直挂着已结束的 CTS。
  修法：Actions.cs:205-226 Arm 改为“锁内只换引用、锁外只 Cancel 不 Dispose”；
        Actions.cs:228 Watch 改收 CancellationTokenSource，整个循环包 try/finally
        （Actions.cs:277-286），finally 里 `if (ReferenceEquals(current, cts)) current = null`
        再 Dispose 自己的 cts（谁创建谁释放，不跨线程释放正在 WaitOne 的句柄）；
        Actions.cs:250 在 RequestJumpTo 之前复查取消；
        Actions.cs:267-275 只在 !IsCancellationRequested 时才写超时日志。
  证明：反射测试「轮询超时常量：120 秒」「Arm 之后有等待中的任务」
        「第二次 Arm 换掉了旧的等待」「被顶掉的旧任务收到取消」
        「旧任务的 CTS 被释放（不再泄漏 WaitHandle 句柄）」（Dispose 后访问 cts.Token 抛出
        ObjectDisposedException 作为判据）「任务收尾后 current 被清空」
        「当前任务的 CTS 也被释放」「Arm(slide=0)/Arm(空路径)/Arm(service=null) 不启动轮询」。

BUG-02 自动化打开课件没有连点护栏（8 秒内重复开同一份）
  现象：自动化动作被点两下，或规则抖动连续触发时，会 Process.Start 两次同一份课件，
        开两个演示实例，第二个把第一个的放映顶掉（老师的翻页就白按了）。
  根因：Automation\Actions.cs:40-105 OpenInBackground 直接 Process.Start（Actions.cs:77），
        与卡片按钮走的 SlideSyncService.OnOpenDeckRequested 不同——后者有 8 秒同路径护栏，
        自动化这条路径完全没有。
  修法：新增 internal static class OpenThrottle（Actions.cs:121-160）：
        RepeatGuardSeconds = 8（与卡片按钮口径一致），IsRepeat(key, nowUtc)（Actions.cs:135）
        在 8 秒内同一 key 返回 true，并且**不刷新计时**（否则连点会无限续期）；
        时钟回拨（nowUtc < lastUtc）不判重复而是重新计时。
        OpenInBackground 在 Process.Start 之前用 Ledger.Key(path) 问一次（Actions.cs:67），
        命中就写“8 秒内已经打开过同一份课件，忽略这次重复触发”并返回。
  证明：「8 秒护栏」11 条：首次不重复、0 秒拦、7.9 秒拦、正好 8 秒放行、8 秒后按新起点重计时、
        不同课件互不影响、空 key 永不算重复、时钟回拨不误判、常量与卡片按钮一致（=8）。

BUG-03 EndSlide=0 的坏记录会让日志说谎（“待跳第 0 页”）
  现象：台账里 EndSlide=0 / 负数的记录被“打开上次未讲完的课件”选中时，
        app.log 写“待跳第 0 页”，但实际不会跳页——日志与行为不一致，排查时被误导。
  根因：Automation\Actions.cs:85-96 直接拿 record.EndSlide 拼日志并调 PendingJump.Arm，
        而 Arm 见到 slide<=0 会立刻 return（Actions.cs:205 起）。
        Automation\UnfinishedDecks.cs:25 的注释还说“EndSlide=0 的坏记录由行动那边跳过”，
        实现里并没有跳过。
  修法：新增 UnfinishedDecks.JumpPage(record)（UnfinishedDecks.cs:35-39，
        EndSlide>0 ? EndSlide : 0）；Actions.cs:85-96 改为 slide<=0 时只记
        “记录里没有可用页码（EndSlide=…），只打开不跳页”并 return，不再调 Arm；
        IsUnfinished 的注释同步改成真实行为（UnfinishedDecks.cs:23）。
  证明：「JumpPage(EndSlide=0) → 0」「JumpPage(EndSlide=-3) → 0」「JumpPage(12) → 12」
        「IsUnfinished：EndSlide=0 且知道总页数 → 算没讲完（规则口径原样）」。

BUG-04 Action 的后台任务没有异常出口（一次异常就永久静默）
  现象：自动化动作偶发“什么都没发生”，app.log 里也没有任何记录。
  根因：Automation\Actions.cs:36 `Task.Run(OpenInBackground)`，而 OpenInBackground 内部
        的台账遍历 / File.Exists / Process.Start 都没有 try/catch；
        Task 上未观察的异常被 GC 时静默丢弃，宿主和日志都看不到。
  修法：Actions.cs:48-104 整段包 try/catch，catch 里写
        “automation: 打开未讲完课件时出错 ” + ex.Message 到台账日志。
  证明：代码级（try 覆盖 NewestUnfinished / ResolveExistingFile / 护栏 / Process.Start / Arm 全程），
        配合 BUG-05 的台账读取改造降低触发面；反射测试「规则：台账为 null → 不成立（安静返回）」
        「NewestRecord(null) → null」覆盖同族“拿不到服务/没有台账就安静返回”的路径。

BUG-05 “最近一条”用 StartedAt 字符串序比较，混排日期格式时选错记录
  现象：同一份课件的台账里既有 “2026/9/8 10:00:00” 又有 “2026-09-30 09:00:00” 时，
        规则「上次课件没讲完」和行动「打开上次未讲完的课件」会认错“最近一条”：
        前者按字符串比较会认为 9/8 更新（'/' 的码位大于 '-'），于是把早已讲完的旧课当最新，
        规则该成立时不成立；行动也可能打开更旧、或与规则判定不一致的那份。
  根因：Automation\Rules.cs:37 原来调 ledger.Newest()，Ledger.Newest（Core\Ledger.cs:306-324）
        用 string.CompareOrdinal(r.StartedAt) 排序；UnfinishedDecks.NewestUnfinished 同样如此。
        而 Core\CardFileList.cs 的 CompareDesc 早就改成解析后的时间，并注释说明
        “纯字符串比较会把 2026/9/8 排到 2026/10/1 后面”——口径不统一。
  修法：UnfinishedDecks.cs 新增 NewestRecord(ledger)（:68-84）、IsNewer(candidate, best)
        （:123-137）与 SortTime(record)（:140-148）：先按解析成功的时间比较（StartedAt 优先，
        失败退 EndedAt），时间相等再退 StartedAt 的 Ordinal，最后退 FilePath，
        保证确定性且不会把不同课件判成同一条；NewestUnfinished 也改用 IsNewer（:106）；
        Rules.cs:37 改用 UnfinishedDecks.NewestRecord，规则与行动从此共用同一口径。
  证明：「NewestRecord：取解析后时间最新的一条（讲完的那条）」——夹具就是
        “2026/9/8 10:00:00”（解析为 2026-09-08）与 “2026-09-30 09:00:00”，
        测试现场打印字符串序的结论（会选旧那条）作为对照；
        「规则：最近一条已讲完 → 不成立」（旧实现会误判为成立）；
        「NewestUnfinished：最近一条没讲完的是旧格式那条」；
        「规则口径（不要求文件）：三份都算，取最新」。

BUG-06 控制面板历史列表按字符串序排，“最新一条”可能错位 → 点“立即跳转”跳到旧页
  现象：历史列表第一行不是真正最新的一次；ControlPanel 的 Select() 用
        history[0].Slide 当“上次停的页”，于是「立即跳转」跳到几节课之前的页码。
  根因：Core\PanelData.cs:87-106 History 直接沿用 ledger.Recent() 的顺序，
        而 Recent（Core\Ledger.cs:257-284）是 string.CompareOrdinal(StartedAt) 降序
        （同秒按写入顺序倒序）——混排日期格式时“最新”是错的；
        Ui\ControlPanel.axaml.cs:206-229 的 selectedPage 依赖 history[0]。
  修法：PanelData.cs:117-144 新增 NewestFirst(ledger, item, max)：
        先 ledger.Recent(key, int.MaxValue)（保留 Recent 对 EndSlide<=0 的过滤与后缀桶回退），
        再对下标做稳定排序（SortTime 降序，时间相同保持 Recent 的“后写入者优先”），最后取前 max；
        SortTime（:147-153）用 DateTime.TryParse(InvariantCulture, None)。
        History 与 TotalSlides 都改走它（:91、:164）。
  证明：「历史：第一行是解析后时间更新的那条（页码 12）」「历史：第二行是旧那条（页码 5）」
        「历史：第一行时间文案 = 10-01 09:00」「历史：坏记录（EndSlide<=0）不显示」
        「历史：max=0/1、台账 null、item null」。

BUG-07 总页数取的是“字符串序最新”那条记录的 SlideCount
  现象：同一份课件换过版本（总页数从 30 变 40）后，面板上「共 N 页」可能显示旧版本的页数。

  证明：「总页数：取最新一条的 SlideCount（30）」
        「总页数：SlideCount 缺、EndSlide 为负 → 0（不显示“共 -4 页”）」「台账 null → 0」。

四、需要别人改的（这两个文件有人在改，我没动）
---------------------------------------------------------
1) 【高】ToggleCardAction 用 Armed 判断“卡片是否可见”（Automation\Actions.cs:178）
   `service.Armed` 的含义是“引擎与卡片正在运行”，不是“卡片可见”。
   卡片被 autoHide 收起、或老师手动点收起后，NativeOverlayCard.expanded=false（private，
   没有公开只读属性），但服务仍然 armed。此时执行「显示悬浮卡片」自动化会走
   HideCardForAutomation → Disarm，把引擎和卡片一起销毁，
