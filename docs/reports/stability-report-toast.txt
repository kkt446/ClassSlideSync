课件续页 2.x · 下课提醒「操作中心横幅」稳定性报告
====================================================

日期：2026-10-24　机器：Windows 11 build 26200（用户态，普通账户 xzq，无管理员权限）
仓库：C:\Users\xzq\Documents\deepseek-harness\default-workspace\ClassSlideSync.Plugin
需求原话：「看看能不能在插件里内置，启用过一次插件就安装这个依赖，要横幅。」

结论（TL;DR）
-------------
* 横幅能力做成了随插件发布的独立小工具 `Tools\ToastHelper\ToastHelper.exe`，插件项目本身
  **没有**加任何 NuGet、TargetFramework 仍是 `net8.0-windows`（ClassIsland 动态加载要求）。
* 插件第一次启用时（`Plugin.Initialize`）后台跑一次 helper 的 `--register-only`，helper 自己把
  HKCU 的 AppUserModelId 键和开始菜单快捷方式写好，然后插件写 `toast-installed.txt` 记账；
  之后每次启动看到标记文件对得上就直接跳过，符合「启用过一次就装好」。
* 横幅发不出去时（helper 不在 / helper 坏了 / 系统关了通知 / 超时）一律**静默返回 false**，
  下课提醒退回原来的托盘气泡；再不行就只记一行日志。录制与 UI 完全不受影响。
* 实测：helper 弹横幅 `exit=0`、操作中心历史里能读回逐字一致的 toast XML；
  插件侧三个用例（helper 正常 / 缺失 / 坏掉）行为全部符合预期。
* **横幅的肉眼可见性没能验证**：验证时这台机器正处于「右上角有全屏游戏 + QQ 在被人用」的状态，
  连系统自带的 PowerShell AUMID 做对照实验也拍不到横幅（见 §6.4）。投递链路已证，显示层受
  当时桌面状态压制，不是 helper 的问题。

1. 要解决什么
-------------
原来的下课提醒走 `Core\TrayNotifier.cs`（`Shell_NotifyIcon(NIF_INFO)` 托盘气泡）。Win11 上这条
路径基本等于「悄悄往通知中心塞一条历史」，不弹横幅、没声音，老师根本看不见。
用户明确要的是 Windows 操作中心里的**横幅（toast）**。

2. 为什么横幅必须放在独立小工具里
---------------------------------
弹 toast 要用 `Windows.UI.Notifications.ToastNotificationManager` + `Windows.Data.Xml.Dom`，
这属于 WinRT 投影，`net8.0-windows10.0.19041.0` 起才有；而插件的 TFM 被 ClassIsland 的
`EnableDynamicLoading` 钉死在 `net8.0-windows`，改不了（改了宿主加载不了），也不允许给插件加
NuGet。于是：

* `Tools\ToastHelper\` 是一个独立 csproj（`WinExe`，`net8.0-windows10.0.19041.0`，
  `SupportedOSPlatformVersion=10.0.17763.0`），自带 WinRT 投影，插件侧一行 WinRT 代码都不沾。
* 插件只通过**命令行**跟它通信（进程隔离，崩了也炸不到 ClassIsland）。

3. helper：命令行协议、退出码、自注册
------------------------------------
文件：`Tools\ToastHelper\`（`Program.cs` / `ToastRegistration.cs` / `ToastShow.cs` / `ShellLink.cs` / `Log.cs`）

3.1 命令行
    ToastHelper.exe --title "…" --body "…" [--aumid <id>] [--log <文件>]
                    [--register-only] [--no-register] [--help]
  * `--title/--body`：横幅两行文字。`--body` 为空视为参数错误。
  * `--log`：把过程追加写进文件（默认不写，因为 helper 可能住在不可写的插件目录里）。
  * `--register-only`：只做自注册，不弹（插件首次启用时用这个）。
  * `--no-register`：跳过自注册直接弹（诊断用，区分「登记不对」和「系统通知不通」）。
  * 默认 AUMID：`ClassSlideSync.Plugin.Toast`。

3.2 退出码（插件据此决定回退）
    0  Ok                     横幅已交给系统（Show 没抛异常）
    10 BadArguments           参数不对
    20 RegistrationFailed     自注册失败（写 HKCU / 建快捷方式 / 读回校验任一步失败）
    30 ShowFailed             CreateToastNotifier / Show 抛异常
    31 NotificationsDisabled  系统里这个应用的通知被关掉了（ToastNotifier.Setting != Enabled）
    40 Unexpected             其他未预期异常

3.3 自注册做了什么（全部用户态，不需要管理员）
  a) 注册表：`HKEY_CURRENT_USER\Software\Classes\AppUserModelId\ClassSlideSync.Plugin.Toast`
       DisplayName = REG_SZ "课件续页"
       IconUri     = REG_SZ "<helper 所在目录>\icon.png"
     写完立刻读回校验（值不相等就算失败）。
  b) 开始菜单快捷方式：`%APPDATA%\Microsoft\Windows\Start Menu\Programs\课件续页通知.lnk`
       TargetPath = <helper 所在目录>\ToastHelper.exe
       属性 System.AppUserModel.ID = ClassSlideSync.Plugin.Toast
     用 `IShellLinkW` + `IPropertyStore`（PKEY_AppUserModel_ID = 9F4C2855-9F79-4B39-A8D0-E1D42DE1D5F3 / 5）
     直接写，不依赖 PowerShell。
     已存在且 target/AUMID 都对 → 复用，不重建（幂等）；对不上 → 重建。
  这两步是 Win32 程序能弹 toast 的前提：系统得能按 AUMID 认出「是哪个应用」。
  注册表与快捷方式都落在 HKCU 和用户自己的开始菜单里，所以**不需要提权**，也不会写插件目录
  （ClassIsland 的插件目录不保证可写）。

3.4 两个真实 bug（都已修，留档）
  * `ShellLink.cs` 共享冲突：`IPersistFile.Save` 之后 COM 对象还占着 .lnk，紧接着
    `SHGetPropertyStoreFromParsingName` 读回报 `hr=0x80070020`（ERROR_SHARING_VIOLATION），
    被误判成注册失败（exit 20）。修法：Save 之后先 `Marshal.ReleaseComObject(pf/link)` 再写属性，
    读回加重试；属性写入 `SetValue/Commit` 都返回 S_OK 但本进程暂时读不回来时，记一行日志并
    **按成功处理**（shell 属性缓存问题，不影响实际生效——已用 Shell.Application 独立验证）。
  * `ToastShow.cs` 的 `ToastNotifier.Setting` 是坑：对一个从没发过通知的 AUMID，读 `Setting`
    会抛 `COMException hr=0x80070490`（ERROR_NOT_FOUND），但 `Show()` 照样成功。原实现直接判失败
    导致 exit 30。改成 try/catch 忽略该异常，只有明确读到「非 Enabled」才返回 31；
    `CreateToastNotifier`、`Show` 各自单独 catch 并记录 HRESULT，日志里能分清是哪一段挂了。

3.5 横幅本身
  ToastGeneric + `duration="long"` + appLogoOverride（icon.png）+ 默认提示音，
  超时时间 = 现在 + 2 小时；文本经 `SecurityElement.Escape`。Show 成功后读一次
  `ToastNotificationManager.History.GetHistory(aumid)` 把条数写进日志，作为「真进系统了」的证据。

4. 插件侧
---------
4.1 `Plugin.cs`（Initialize 里，注册服务之前）
    `ToastNotifier.InstallOnce(PluginConfigFolder);`
    只做一次检查：算出 helper 路径 → 后台 `Task.Run` 里判断
      · helper 不存在 → 记日志「用托盘气泡」，结束；
      · `PluginConfigFolder\toast-installed.txt` 里 version=1 且 helper 路径一致 → 直接置 ready；
      · 否则跑 `ToastHelper.exe --register-only --log <cfg>\toast-helper.log`，exit=0 才置 ready
        并写标记文件（version/helper/installed 三行）。
    为什么开线程：Initialize 在 ClassIsland 启动链上，不能为一条通知拖慢启动。

4.2 `Core\ToastNotifier.cs`（新增，301 行）
    `IsReady` / `InstallOnce(cfg)` / `Show(title, body)`，全 static、全 internal。
    * helper 路径 = 插件 dll 所在目录 + `ToastHelper\ToastHelper.exe`
      （用 `Assembly.Location`，**不能**用 `AppContext.BaseDirectory`——那是 ClassIsland 进程目录）。
    * `Show` 里：`_ready` 为假 → false；连续失败 ≥3 次 → 本次会话不再试（免得每次下课白起进程）；
      进程 8 秒超时 → Kill + false；helper 突然消失 → `_ready=false` + false；所有异常吞掉。
    * helper 用 `UseShellExecute=false, CreateNoWindow=true` 起，参数按 Windows 命令行规则加引号
      （标题里有引号也不会被拆成两个参数）。
    * 自己的日志：`PluginConfigFolder\toast-plugin.log`（>512KB 停写）、`toast-helper.log`（helper 侧）。
    * `PluginConfigFolder` 为空时退到 `%LOCALAPPDATA%\ClassSlideSync.Plugin`，避免相对路径把文件
      撒进 ClassIsland 的进程目录。

4.3 回退链（`Services\SlideSyncService.cs` 的 `MaybeNotifyClassEnd`，约 465-470 行）
    ```
    if (ToastNotifier.Show(title, text))            ledger.Log("notify: toast " + text);
    else if (TrayNotifier.Show(title, text))        ledger.Log("notify: balloon " + text);
    else                                            ledger.Log("notify: 系统不让弹（横幅与托盘气泡都失败）");
    ```
    文案没动：`title = "课件续页 · <科目>"`，`text = "「<课件名>」记到第 N 页，还剩 M 页"`。

5. 打包：helper 怎么跟着 .cipx 走
--------------------------------
`ClassSlideSync.Plugin.csproj` 里加了两个 target（插件 TFM 与依赖都没动）：
  * `BuildToastHelper`（BeforeTargets=Build，带 Inputs/Outputs 增量）：
    `<Exec Command="&quot;$(DOTNET_HOST_PATH)&quot; build &quot;Tools\ToastHelper\ToastHelper.csproj&quot; -c $(Configuration)" />`
    为什么用 Exec 起子进程而不是 MSBuild 任务：MSBuild 任务会把主工程的全局属性
    （TargetFramework 等）带进子工程，helper 的 TFM 会被覆盖成 net8.0-windows，WinRT 投影就编不出来。
  * `CopyToastHelper`（AfterTargets=Build）：把 helper 的整个输出目录拷到
    `bin\Release\net8.0-windows\ToastHelper\`，并把目标登记进 `FileWrites`（Rebuild/Clean 会清掉旧货）。
  另外保留了 `Compile/AvaloniaXaml/AvaloniaResource/EmbeddedResource/None Remove="tools\**"`，
  否则主工程的默认通配对把 helper 的 .cs 和 obj 里的生成文件一起吞进来（CS0579 重复特性）。

构建后输出目录实测（7 个文件，全部进 .cipx）：
    ToastHelper.exe                  151,552
    ToastHelper.dll                   17,920
    ToastHelper.deps.json              1,085
    ToastHelper.runtimeconfig.json       340
    icon.png                          32,770
    WinRT.Runtime.dll                528,944
    Microsoft.Windows.SDK.NET.dll 24,877,600
体积影响（实测，必须说清楚）：helper 解包后约 **24.4 MB**，其中 `Microsoft.Windows.SDK.NET.dll`
一个就 23.7 MB。但打包是 zip（deflate），实际 `.cipx` 只从 0.14 MB 涨到 **6.93 MB**
（`Microsoft.Windows.SDK.NET.dll` 压到 6.43 MB，`WinRT.Runtime.dll` 528 KB → 187 KB，
`ToastHelper.exe` 151 KB → 68 KB）。
后续可优化方向（本次没做）：CsWinRT 裁剪投影 / 改成手写 `RoGetActivationFactory` 的 COM 互操作，
只保留 `ToastNotificationManager`、`XmlDocument` 几个接口，可把 helper 压到几百 KB、.cipx 回到 1 MB 以内。

6.4 横幅「肉眼出现」这件事：没验证成功，原因如下
    * 用 `Graphics.CopyFromScreen` 连拍右上角（470x230，20 帧 @200ms + 8 帧 @700ms + 对照拼图），
      全部没有横幅；`ms-actioncenter:` 也没能打开操作中心。
    * 对照实验：用系统自带的 PowerShell AUMID（`{1AC14E77-02E7-4E5D-B744-2EB1AE5198B7}\WindowsPowerShell\v1.0\powershell.exe`）
      弹一条已知能用的 toast，同样拍不到横幅 → 说明是这台机器当时的通知显示状态在压制横幅
      （截图时右上角有全屏游戏窗口、QQ 正在被真人使用，Windows 11 的「玩游戏/全屏时勿扰」会自动生效；
      `Notifications\QuietHours\QuietHoursServiceState=0`，全局无通知策略键）。
    * 因此证据链止步于「系统收下了这条通知」：`Show()` 没抛异常（exit 0）+ 操作中心历史读回逐字一致
      + 系统按 AUMID 记了 `LastNotificationAddedTime`。真实横幅需要用户不在游戏/勿扰时再跑一次确认。
    * 复现命令（任意用户态命令行，helper 需在可写位置，不要从插件目录里跑注册）：
        "%TEMP%\toastselftest\A\ToastHelper\ToastHelper.exe" --title "课件续页 · 通知自检" --body "这是一条测试横幅，不会重复出现" --log "%TEMP%\toast-manual.log"
