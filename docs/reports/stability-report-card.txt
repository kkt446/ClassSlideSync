  1 展开态：卡片最下面倒数第二行是一条 4px 高的横向进度条，按「已讲页数/总页数」把长度切成

    （药丸矩形固定 L=0..tabWidth）。从卡片左边缘向内拖仍然是移动窗口的手势（>4px 即拖动），

2) 左边缘竖把手（整条高度可点，药丸落在同一条竖带上）
   internal static Rect32 RailRect(int width, int height, int dpi)
   {
       int S(int v) { return (int)Math.Round(v * dpi / 96.0); }
       if (width <= 0 || height <= 0) return new Rect32(0, 0, 0, 0);
       return new Rect32(0, 0, Math.Min(S(HandleWidth96), width), height);
   }

3) 进度换算（横向/竖向共用同一套夹取规则）
   internal static double ProgressRatio(int page, int total)
   { if (total <= 0 || page <= 0) return 0; if (page >= total) return 1; return page / (double)total; }

   internal static int PillFillHeight(int height, int page, int total)
   {
       if (height <= 0) return 0;
       int hh = (int)Math.Round(height * ProgressRatio(page, total));
       if (hh < 0) hh = 0;
       if (hh > height) hh = height;
       // 讲了一页也要看得见：算出 0 但确实讲过时至少留 2px，否则会被圆角整段吃掉。
       if (hh == 0 && page > 0 && total > 0) hh = Math.Min(height, 2);
       return hh;
   }

6) 「还剩 N 页 · 约 M 分钟」放不下时的逐级退让
   string FitRemain(GdiCanvas g, string text, int maxWidth)
   {
       if (string.IsNullOrEmpty(text) || maxWidth <= 0) return text ?? "";
       if (g.TextWidth(text, g.FontSub2) <= maxWidth) return text;
       string t = text.Replace(" · 约 ", " · ");                     // 先砍「约」
       if (g.TextWidth(t, g.FontSub2) <= maxWidth) return t;
       if (t.StartsWith("还剩 ", StringComparison.Ordinal))           // 再把「还剩」缩成「剩」
       { t = "剩 " + t.Substring(3); if (g.TextWidth(t, g.FontSub2) <= maxWidth) return t; }
       return t;                                                     // 都放不下才交给 Ellipsis
   }

八、看图后改掉的 5 处（都是先出图看见问题再改，改完重出图）
------------------------------------------------------------
1) 大页码原来是 accent 橙色：40px 的橙数字把整张卡的重心全抢走，跳转按钮反而不像主操作；
   按视觉规格「页码 40px 加粗（深色）」改成正文字色（st.Showing ? accent : text → text）。
2) 「还剩 17 页 · 约 17 分钟」被截成「还剩 17 页 · 约 17…」：右列只有 124px。两处一起改——
   页码列改成按数字实际宽度收窄（一位数只占 46px，省出 22px），再加 FitRemain 逐级退让兜底。
   现在 17 页这种三位数字的状态也是完整一句话。
3) 药丸 30% 时填充被画成一颗圆球（圆角取半宽 10px + 填充只有 18px 高）：圆角降到 4px，
   填充才读得出是「条」。
4) 左边缘竖带 Mix 0.06 在 #EEEEEE 上几乎看不见（#EEEEEE → #E9E9EA）：提到 0.10，
   箭头从 FontSub2 放大到 FontSmall。
5) 齿轮 24px 下轮盘 0.30、齿宽 0.17 画出来像雪花，认不出是「设置」：轮盘 0.34、齿 0.22、
   内 0.29、外 0.47、孔 0.11，形状变 chunky，8 齿看得出是齿轮。

   跑一遍。竖带命中区覆盖整卡高度这点是测过的。
3) 药丸位置的一个已知副作用：贴右（默认 OnRight=true）时，收起后的药丸停在卡片左边缘、
   离屏幕右边缘还有 cardWidth-tabWidth = 204px，不再像改版前那样紧贴屏幕边。原因是老师要求
   「药丸和竖带落在同一条线上」，而竖带只可能在卡片左边缘。这是设计选择不是 bug，
   代码注释（Place）与本报告都写明了；如果老师更想要「药丸贴屏边」，只需把 Place 的收起分支
   改回 screenRight-tabWidth / screenLeft+tabWidth-cardWidth，两行的事。
4) 144dpi 那两张是把私有字段 dpi 压到 144 后重排重画的，不是真的把显示器缩放改成 144 再跑；
   相当于验证了「按 144dpi 计算出来的几何 + 绘制」，没验证系统级 DPI 迁移。
5) 控制面板窗口（Ui\ControlPanel.axaml，另一个子 agent 的活）没验证内容与排版，只验证了
   「点齿轮 → PanelRequested 触发一次」这条链路（Service 里 OnPanelRequested 是既有代码，未改）。
6) 历史面板的正文文案（另一个子 agent 正在改）我没动、也没复验，只保证历史行点击仍打开面板。
7) 没测 CardScale≠1、自定义圆角（设置页可改）、暗色主题：这些只读了 Appearance.Resolve 的代码，
   没有出图。正文颜色一律取 look 的 text/muted（没有硬编码 #1B1C1E），暗色主题理论上不会翻车，
   但没有实际图。
8) 「进度条按已讲页数/总页数分段」是长度分段，没有画刻度或分段线；如果老师想要“一格一页”的
   分段观感（像课程时间条的分钟刻度），需要再加一层刻度绘制——目前没做。
