======================================================================
二、颜色解析规则
======================================================================

字段：Core\SyncSettings.cs 的 PanelBackgroundColor（string，默认 "#FFFFFFFF"）。
setter 自己会 Trim、补 '#'、统一转大写（ToUpperInvariant），所以代码里读到的一定是
"#FFFFFF" 或 "#AARRGGBB" 这种大写串。

解析（ControlPanel.BrushFrom）：
  - 空白串        → 直接返回 fallback；
  - 没有 '#'      → 自动补一个（老师手写 FFFFFF 也认）；
  - 6 位 "#RRGGBB" → 不透明色；
  - 8 位 "#AARRGGBB" → Alpha 在最前面（Avalonia 自己的口径）；
  - Color.TryParse 失败（#ZZZZZZ、#12345 之类）→ 返回 fallback。
  - fallback 固定是纯白 SolidColorBrush：写错一位不能让窗口变透明或变黑，
    那样看起来像程序崩了。

写回（HexColorConverter.ConvertBack）：一律输出 8 位大写 "#AARRGGBB"，和上面同一个口径。
读回（Convert）：解析失败显示白色，与 BrushFrom 的兜底同色，于是面板和设置页那一小块
颜色不会各显示各的。

半透明：底色的 Alpha < FF 时窗口就是普通半透明窗口（没有亚克力合成），会直接透出背后
的内容。想要"毛玻璃再压一层色"的老观感，这一版刻意没有。

口径冲突提醒（下一轮别踩）：卡片那几个颜色字段走 Core\Appearance.cs:220 TryParseColor，
那边 8 位按 "RRGGBBAA"（Alpha 在后）解释；面板底色这一条按 "#AARRGGBB"（Alpha 在前）。
两套口径不能混用。

======================================================================
三、深底对比度怎么处理
======================================================================

做法：底色偏暗时把本窗口子树的主题变体切到 Dark（正文转浅色），偏亮时切回 Light
（正文保持深色）。只动 ControlPanel 这一个窗口的 RequestedThemeVariant，不碰
Application.Current.RequestedThemeVariant，宿主 ClassIsland 的主界面不受影响。

为什么不"正文固定深色"：底色是老师自己配的，深色底 + 深色字必然不可读；而面板里
正文/次要文字/列表项/状态条几乎都是 TextFillColorPrimary/SecondaryBrush 这类主题画刷，
逐个改 Foreground 压不住（TabControl、SettingsExpander、Button 的模板里还有各自的画刷），
改变体只有一处判断，并且能连带把开关、按钮、卡片一起换过来。

阈值 0.45（ControlPanel.axaml.cs:169）：
  RelativeLuminance 用朴素公式 (0.2126R + 0.7152G + 0.0722B)/255，没做 sRGB 线性化。
  画刷颜色和阈值都是同一个公式算出来的，互相可比；朴素公式的副作用是深蓝/深红这类
  颜色会被算得偏亮，判成"浅底"用深字 —— 方向是安全的（深字对深蓝仍然比白字清楚）。
  0.45 是二分点的选择：中灰 #808080 亮度 0.500 判浅底，深字约 8.8:1；
  若判成深底，白字对 #808080 只有约 3.9:1，反而更差。

踩到的坑（重要）：只改 RequestedThemeVariant 不够。FluentAvalonia 的 SettingsExpander
卡片（设置页每一行的底色）是启动时按当时的主题变体解析好、之后就冻住的画刷；运行中改
窗口变体时文字会跟着变（ClassIsland 自己的 ThemeDictionaries 是变体感知的），卡片却还是
浅色 —— 深底上就是"浅灰卡片 + 浅色正文"，白字压浅底，约 1.8:1，正是这条要求要避免的。
实测：冷启动就是 Dark 时卡片是 #0DFFFFFF（正常深色档），运行中切变体后仍是 #B3FFFFFF。
解法（ControlPanel.axaml.cs:190 NudgeThemeResources）：切完变体后往窗口 Resources 里塞一个
换过值的无关键（PanelColorThemeNudge = 新 Guid），触发一次 ResourceChanged，那批画刷就按
新变体重新解析（实测 #B3FFFFFF → #38FFFFFF）。必须 Post 到下一轮：变体本身是异步传播的，
同一帧里重算还会读到旧变体。

效果实测（离屏渲染取像素）：
  - 默认 #FFFFFFFF：正文 #1B1C1E 系，白底，约 17:1；
  - #FF1B1C1E：正文 #EDEDED，卡片混合后约 #4D4D4D，约 7:1（粗略估算，肉眼清楚）。
