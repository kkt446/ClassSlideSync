一、分组 / 大分支 API 结论
--------------------------------------------------------------------
结论：**有，能用，而且不需要自己造轮子。**

1) 程序集里的真实签名（ILSpy 反编译
   classisland\app-2.1.0.1-0\ClassIsland.Core.dll，
   ClassIsland.Core.Attributes.ActionInfo）：

       public ActionInfo(string id, string name, string? iconGlyph = null,
                         bool addDefaultToMenu = true, string defaultGroupToMenu = "")

2) 注册链路（ClassIsland.Core.Extensions.Registry.ActionRegistryExtensions）：

       AddAction<TAction>()          → RegisterActionInfo(typeof(TAction)) → ProcessAddToGroup(info)
       ProcessAddToGroup(info)       → info.AddDefaultToMenu 为 false 直接 return；
                                        info.DefaultGroupToMenu 非空时，在 IActionService.ActionMenuTree
                                        里按名字找 ActionMenuTreeGroup；
                                        找不到就 new ActionMenuTreeGroup(name, null) 加到根集合；
                                        最后把 new ActionMenuTreeItem(info.Id, info.Name, info.IconGlyph)
                                        塞进该组的 Children。

   也就是说：**只要给 [ActionInfo] 的第 5 个参数写一个组名，插件自己就出现在「添加行动」菜单的
   那个组里；组不存在时 ClassIsland 会自动建一个根组**，下一次注册同名的行动会并进同一个组。

3) 官方文档情况：
   - 开发文档 https://docs.classisland.tech/dev/automation/ **HTTP 404**（页面正文「页面不存在」），
     官方没有自动化开发文档，只能以程序集签名为准；
   - API 文档 https://api.docs.classisland.tech/api/ClassIsland.Core.Attributes.ActionInfo.html 有
     构造函数说明，`defaultGroupToMenu` 原文：「在「添加行动」菜单添加默认项的根菜单组。
     如果找不到该组会添加该组。默认为根菜单。」——与本插件用到的行为一致。

4) 实际用法（本插件）：
       [ActionInfo(Id, Name, Glyph, true, AutomationGroups.Plugin)]
   `AutomationGroups.Plugin` = "课件续页"（Automation\UtilityActions.cs:17-21）。
   五个行动共用这个常量，组名只有一处定义。

   注意点（写在这里备查）：
   - 第 4 个参数 `addDefaultToMenu` 必须是 true，否则压根不进「添加行动」菜单（只进代码注册表）；
   - 组名是全局的（挂在宿主的 IActionService.ActionMenuTree 上），如果别的插件也用「课件续页」
     会并进同一个组，所以名字取了插件中文名；
   - 组内顺序 = 注册顺序（Plugin.Initialize 里 AddAction 的调用顺序）。

       public string Message { get; set; } = "来自自动化";

     执行：TrayNotifier.Show(title, message)（Core\TrayNotifier.cs 已有，15 秒后自己摘托盘图标），

     为什么不用 ToastNotifier：托盘气泡在教室机器上比系统 Toast 稳（不依赖通知开关/聚焦助手），
     而且 TrayNotifier 是插件里已经用了一学期的现成实现，不需要任何 NuGet。

  2) OpenPanelAction —— 「打开课件续页控制面板」（UtilityActions.cs:88-126）
     Id          = "ClassSlideSync.Plugin.OpenControlPanel"
     Name        = "打开课件续页控制面板"
     Description = "把插件自己的控制面板叫到前台：里面有课件台账、跳页、设置入口。上课没开始（服务未 Arm）时不动作，只记日志。"
     Glyph       = "\uE8A7"（OpenPane）
     执行：SlideSyncService.OpenPanelForAutomation("自动化：打开控制面板")。
     为什么加方法：面板原本只有「点托盘图标 → OnPanelRequested()」这一条创建链路，而且
     OnPanelRequested 是 private；自动化需要一个公开入口，所以只加了这一个最小公开方法
     （Services\SlideSyncService.cs:1239-1256），内部就是「记日志 + 转调既有 OnPanelRequested()」，
     不复制任何面板创建/线程切换逻辑。没 Arm 时主动 return 并记
     "automation panel: 没在上课（未 Arm），跳过：..."，让日志能区分「跳过」和「失败」。

  3) JumpLastPageAction —— 「跳到上次停的那一页」（UtilityActions.cs:136-214）
     Id          = "ClassSlideSync.Plugin.JumpLastPage"
     Name        = "跳到上次停的那一页"
     Description = "在当前正在放映的课件里，跳回台账记录的最后一页；没有在放映或没有记录时安静跳过，只记日志。"
     Glyph       = "\uE7C3"（Page）
     执行：engine.Last（当前放映的那份）→ ledger.Last(filePath) → UnfinishedDecks.JumpPage(record)
           → service.RequestJump(page)。
     为什么这么绕：不能拿「台账里最近一条记录」的路径直接去 RequestJumpTo(filePath, page)——
     引擎在桥（PptBridge）没挂上时会 PptBridge.Launch(jumpPath)，等于在教室里凭空拉起一个
     PowerPoint。所以只传页码（service.RequestJump(page) → engine.RequestJumpTo(null, page)），
     文件路径由引擎自己用当前记录解析，目标永远是「正在放映的这份」。

三个行动的公共形状（与既有 ToggleCardAction 一致）：
  - 都是 `public sealed class ... : ActionBase`；
  - 都是 `protected override Task OnInvoke()`，首行 `base.OnInvoke()`，返回 Task.CompletedTask；
  - 都没用 ActionBase<TSettings>：Notify 只有两个短字符串，另两个无属性，为它们各配一个设置类型 +
    设置界面不划算（ClassIsland 的 ActionSettingsControlBase 还得自己写 UserControl）。
    反射测试专门断言了 OpenPanelAction / JumpLastPageAction 没有多余公开设置属性。

四、Invoke 的失败路径（都安静失败，不把异常抛回 ClassIsland）
--------------------------------------------------------------------
NotifyAction
  - Title/Message 为 null → 统一成 ""；TrayNotifier.Show 正文为空时返回 false
    （Core\TrayNotifier.cs:106 起：text 空白直接 false）；
  - Win32 Shell_NotifyIcon 失败（没托盘、系统拒绝）→ 返回 false；
  - 以上两种都会把 LastShowSucceeded=false 并记 "automation notify: 气泡没发出去（标题或正文为空，或系统拒绝）"；
  - TrayNotifier 内部异常被它自己 catch（返回 false）；外层再包一层 catch，记 "automation notify failed: ..."。

OpenPanelAction
  - IAppHost 还没起来 / 服务没注册 → TryService() 返回 null → 记 "automation panel: 服务还没起来，忽略"；
  - 没 Arm（没开始上课）→ OpenPanelForAutomation 记 "没在上课（未 Arm），跳过：..." 后 return；
  - 面板已存在 → OnPanelRequested 走 Show / 还原最小化 / Activate（不新建）；
  - 面板构造或 Show 抛异常 → OnPanelRequested 自己记 "panel open failed: ..." /
    "panel dispatch failed: ..."；OpenPanelForAutomation 外层 catch 兜底记 "automation panel failed: ..."。

JumpLastPageAction
  - 服务为 null → "automation jump: 服务还没起来，忽略"；
  - engine 为 null（没开始放映）→ "automation jump: 还没开始放映，没有可跳的页"；
  - engine.Last 为 null / AppFound=false / FilePath 为空 → "automation jump: 当前没有正在放映的课件，跳过"；
  - ledger 为 null 或 ledger.Last(filePath) 为 null → JumpPage 返回 0 → "台账里没有「xxx.pptx」的有效页码，跳过"；
  - JumpPage 只在 EndSlide > 0 时返回页码（Automation\UnfinishedDecks.cs），所以「没讲到过第几页」也算跳过；
  - service.RequestJump 抛异常 → "automation jump failed: ..."。
  以上日志全部通过 Ledger.Log 落到插件台账（和既有 "automation hide card" / "jump ignored" 同一套前缀），
  在控制面板的日志里能直接看到是跳过还是失败。
