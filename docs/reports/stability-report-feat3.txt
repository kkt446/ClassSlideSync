2) 读课表（Core\LessonTag.cs:135-160）—— 每一处都可能拿不到，一律不抛
        public static LessonTag Read(DateTime now)
        {
            var tag = new LessonTag();
            tag.Weekday = WeekdayOf(now);
            try
            {
                var lessons = IAppHost.TryGetService<ILessonsService>();
                if (lessons == null) return tag;

                var subject = lessons.CurrentSubject;
                if (subject != null && !string.IsNullOrWhiteSpace(subject.Name)) tag.Subject = subject.Name.Trim();

                var item = lessons.CurrentTimeLayoutItem;
                if (item != null) tag.PeriodName = Clean(item.BreakName);

                tag.Period = PeriodAt(SlotsOf(PlanOf(lessons, now)), now.TimeOfDay);
                tag.LessonName = tag.PeriodName.Length > 0
                    ? tag.PeriodName
                    : (tag.Period > 0 ? "第 " + tag.Period.ToString(CultureInfo.InvariantCulture) + " 节" : "");
            }
            catch
            {
                // 读课表失败 = 当作"不知道是哪节课"，历史行退回日期格式，插件照常记页码。
            }
            return tag;
        }

3) 第几节（Core\LessonTag.cs:83-98）—— 只数 TimeType == 0（上课）
        public static int PeriodAt(IList<Slot> slots, TimeSpan at)
        {
            if (slots == null) return 0;
            int n = 0;
            for (int i = 0; i < slots.Count; i++)
            {
                var s = slots[i];
                if (s == null || s.TimeType != 0) continue;
                n++;
                // 起止写反的时段（跨零点、或老师手工填错）不参与判断，但节号照样占一位，
                // 免得它后面所有节的号码整体往前挪一格。
                if (s.End <= s.Start) continue;
                if (at >= s.Start && at < s.End) return n;
            }
            return 0;
        }

4) 文案（Core\HistoryLine.cs:48-76）
        public static string[] Variants(int weekday, int period, string startedAt,
                                       int startSlide, int endSlide, DateTime today)
        {
            string slot = Slot(weekday, period);
            string pages = Pages(startSlide, endSlide);
            string clock = Clock(startedAt);
            string whenFull = When(startedAt, today, true);
            string whenDay = When(startedAt, today, false);

            var list = new List<string>(4);
            if (slot.Length > 0)
            {
                // 有节次就不写日期了：周几 + 第几节已经能定位到具体一节课，再写日期是多余的字
                Add(list, Join(slot, clock, pages));
                Add(list, Join(slot, pages));
            }
            else
            {
                Add(list, Join(whenFull.Length > 0 ? whenFull : whenDay, pages));
                Add(list, Join(whenDay, pages));
            }
            Add(list, pages);
            return list.ToArray();
        }

九、取舍与风险（都说清楚）
================================================================================
1) 「有节次时不写日期」是按需求给的样例做的。副作用：同一个课件、同一个「周三 第 3 节」、
   不同周的两条记录，文案会一模一样（只有页码和时间可能不同）。台账里 StartedAt 仍然是
   完整的 yyyy-MM-dd HH:mm:ss，控制面板（PanelData.cs 的三列视图）另有一列时间可看。
   如果老师反馈"看不出是哪一周"，最小改动是把 Clock 换成 When（一行）。
2) PeriodName 语义：取的是 TimeLayoutItem.BreakName，也就是课表里那个时段的名字。
   如果老师课表没给时段命名，PeriodName 为空，LessonName 会退成「第 3 节」——写进台账的
   是"第 3 节"而不是课程名。这是 ClassIsland 2.1 的 API 限制（TimeLayoutItem 没有 Name，
   要拿课程名得再查 ProfileService 的 SubjectId → Subject，代价大且容易拿到错的）。
3) 快照有最多 2 秒的滞后：BeginSession 读到的是调度器上一跳（≤2 秒前）的课表。上课铃响
   前后那 2 秒内开始的记录，理论上可能记成上一节/下一节。正常路径是调度器先刷新、再 Arm、
   引擎才 BeginSession，实际窗口比 2 秒更小。
4) 引擎线程绝不去碰宿主服务：BuildState 每个心跳都调 lessonContext，所以那边只读
   volatile 快照；真正读课表的是调度器线程。这条是硬约束，改动时别破坏。
5) 老记录（老师现在的 39 条）Period = 0，历史行一律显示日期格式——这是预期行为，不是
   回归。它们不会"补上"节次，因为当时没记。
6) 警告从 186 涨到 193（我这边 +3，其余是并发任务改的文件，且它自己还在变动）。没有为了消警告去改
   SessionRecord 的既有风格（加 = ""），那会和仓库现有写法不一致。
7) DrawHistoryPanel / FitHistory 是私有方法（GdiCanvas / Color32 私有嵌套），测试只能靠
   反射调。以后如果想让测试更稳，可以考虑把几何常量抽成 internal const，但这次没动。

十、没做到 / 没验证的部分（直说）
================================================================================
* 没有启动 ClassIsland（铁律），所以**没有端到端验证**"真实上一节课 → 台账里真的出现
  Weekday/Period/Subject"。验证到的是：API 签名与 SDK 一致（反射核实）、Read() 在无宿主
  环境下不抛且退回日期格式、引擎侧写入路径的字段搬运（BeginSession 的代码读过、断言覆盖
  了 HistoryLine 与 SessionRecord 往返）。真实宿主里 CurrentSubject / CurrentTimeLayoutItem
  的取值时机（尤其课间时 CurrentTimeLayoutItem 是不是课间项）没有实测。
* 没有碰老师真实的 data 目录，也没有在真实台账上跑一遍（只用构造的老/新 JSON 测）。
  所以"39 条老记录渲染成日期格式"是按代码推断的，不是在老师那 39 条上渲染出来的。
* 只验证了 96 dpi 与 144 dpi（比例 1.5）。120 / 192 等其他缩放没测；按 Scaled() 的线性
  关系推断没问题，但没有实测。
* 点击历史行跳页的交互没有真人点过（命中矩形逻辑只是从 Paint 里原样搬进
  DrawHistoryPanel，坐标计算一个字没改，但没实测）。
* 没有在真机上跑单元测试框架（xUnit 之类），断言是自建的小 harness；仓库里也没有测试工程
  （按铁律，测试代码只放在 %TEMP%，不进仓库）。
* 卡片宽度改配置（CardWidth 不是 236）时，文案降级仍然会按 inner 自动挑写法，但没有为
  特别窄/特别宽的自定义宽度出图验证。
* 没有做"台账里同时有老记录（Period=0）和新记录"的历史面板出图（两种格式混排只从我读
  代码判断是安全的：同一行高、同一字体、左对齐、各自按宽度降级）。
