结论
--------------------------------------------------------------------
1. 课件被改过（指纹变 / 页数变）时，能把「上次停在第 N 页」映射到新版对应页；
   映射可信（Kind=Exact/Shifted）才给页码，证据不足一律给「课件改过了，页码可能不准」，
   整份换掉时连页码都不给（NewSlide=0）。不启动 WPS/PPT/LibreOffice，纯托管解 OpenXML。
2. 台账里的路径失效时，在「科目文件夹 + 原件所在目录（含子目录）」里按
   「文件名相似 + 内容指纹相同/相似 + 每页文字相似」找候选；唯一命中才改台账并记
   `relink:` 日志，歧义或没命中就保持「找不到文件」，绝不错挂到别人的课件上。
3. 构建 0 error（218 warning 全部是仓库既有风格告警，本次改动文件 0 条警告）。
4. 反射自测 167 条断言全过（要求 ≥50）。
5. 需要引擎接线才能生效：本报告最后两节写明「在哪里调」——我按约定没有改 SessionEngine。

Core/DeckRemap.cs（新建，1300 行，namespace ClassSlideSync.Plugin.Core，纯托管 + System.IO.Compression）
  区域 1  OpenXML 读取
    DeckPage { string Text; string Title; bool IsEmpty }        // Text=整页所有 a:t，Title=第一段
    DeckPages { string Path; string Fingerprint; List<DeckPage> Pages; int Count; Page(int) }
    DeckReader.CanParse(path) -> bool                           // 只认 .pptx/.pptm/.ppsx
    DeckReader.Read(path) -> DeckPages?                         // 读不出来返回 null，从不抛
      页序按 ppt/presentation.xml 的 <p:sldId r:id> + ppt/_rels/presentation.xml.rels 解析，
      ResolvePart 处理 ../ 与绝对路径 —— PowerPoint 删页后 slideN.xml 编号是稀疏的（1,3,7,9…），
      按文件名数字排序会串页；只有 sldIdLst 缺失时才回退到数字排序。
      每页用 XmlReader 取 a:t（a:p 结尾成段），跳过 <p:pic> 等无关节点，不解整棵树。

  区域 2  相似度（全静态纯函数，便于单测）
    Normalize(s)               小写、全角转半角、空白/标点/符号换成 \u0001 分隔、去首尾
    Dice(a,b)                  字符二元组多重集 Dice，0..1
    PageSim                    0.75*正文Dice + 0.25*标题Dice
    ContentSimilarity(old,new) 旧版均匀抽 ≤8 页，每页在新版里找最像的一页，取平均
    NameSimilarity(a,b)        去掉扩展名 / 「副本 拷贝 复件 copy」/ 尾部 (1)(2) 与 v2 之后再比；
                               子串关系给 0.75+0.25*长度比

  区域 3  页码对齐  MapPage(oldPages, newPages, oldSlide) -> RemapResult
    RemapKind { None, Exact, Shifted, Uncertain, Replaced, Unavailable }
    RemapResult { Kind, OldSlide, NewSlide, OldCount, NewCount, Shift, Confidence, Note, Usable }
    Usable = Kind ∈ {Exact, Shifted}        // 卡片只有在这里才敢跳
    ① 归一化文字完全相同 → Exact（置信度 1.0）。唯一命中才算；多份一模一样的页走②或判重复。
    ② 上下文偏移投票：取旧第 N 页前后各 3 页，各自在新版窗口里找最像的一页，
       用「新索引-旧索引」加权投票（票数≥2 且权重≥1.1 才算数；
       投票给出的候选页自身相似度须 ≥0.45，均分 ≥0.55 才采信）→ Shifted。
       删页/插页会让整段课件平移同一页数，这一级是主力。
    ③ 没有上下文共识时退到单页最佳匹配：相似度 ≥0.62，且比第二像的页高出 ≥0.08，
       同分偏向原位置（距离奖励 0.03）→ Shifted。
    ④ 相似度 0.30~0.62 → Uncertain（给个大致页码 + 「页码可能不准」）；
       <0.30 → Replaced（NewSlide=0，不给页码，提示找不到对应页）。
    ⑤ 旧页没字（纯图片页）→ 只有邻居投票够一致（≥3 票、均分≥0.70）才 Shifted，否则 Unavailable。
    ⑥ 页码超界（旧 12 页停在第 12 页、新版只剩 10 页）夹到最后一页去找，结论里仍写原始页码。

  区域 4  按台账取旧版  RemapFor(ledger, record, currentPath, oldSlide, cacheFolder=null)
    - 指纹相同且页数相同 → Exact「课件没改过，页码不变」。
    - 否则用 record.Fingerprint 去页面留底缓存里取旧版每页文字；取不到 →
      Unavailable「课件改过了，页码可能不准：没有旧版第 N 页的留底」，并顺手把新版存进缓存。
    - 取到 → MapPage，然后把新版也存缓存（下次再改就有两份留底）。

  区域 5  页面留底缓存  DeckPageCache（ledger.Root\deckpages.json）
    台账里只有指纹、没有每页文字，旧版被改掉后原文件就没了，所以必须提前按指纹留一份。
    MaxEntries=80、每页文字截 600 字、标题截 200 字、原子写（写 .tmp 再 File.Replace/Move）；
    读写失败一律吞掉——缓存写不进去只是「下次没法对齐」，不影响上课。
    DeckRemap.CacheFor(folder) 静态注册表复用实例；Remember(folder,deckPath) / Cached(folder,fp)。

  区域 6  移动/改名重关联
    RelocateResult { bool Found; string Path; string Note; List<RelocateCandidate> Candidates }
    RelocateCandidate { Path, Fingerprint, NameScore, ContentScore(-1=没算), SameFingerprint, Score, Accepted }
    FindMoved(missingPath, fingerprint, folders, cacheFolder=null, maxFiles=400)
      候选目录 = 传入目录（科目文件夹）+ 原件所在目录，SearchOption.AllDirectories，最多 400 份，
      跳过 ~$ 临时文件与非 pptx；排除 missingPath 自己。
      逐份：NameScore；Fingerprint（Ledger.Fingerprint，头尾各 64KB + 长度）；
        同指纹 → Score=1.0+0.5*名字分，直接接受（内容一字节不差，改名也认）；
        否则若有旧版留底 → 最多比 14 份的每页文字，Score=0.55*内容+0.45*名字，
          接受线：(内容≥0.85 且 名字≥0.50) 或 (内容≥0.70 且 名字≥0.80)；
        没有内容证据（旧记录没指纹 / 候选读不出来）→ Score=0.25*名字，只有 名字≥0.92 才接受。
      接受份数 ≥2 且头两名分差 <0.08 → 判歧义，不关联，
        提示「找到 N 份都像的课件，先不自动关联」（接错比找不到更糟）。
      成功 → Note「已重新关联：文件名」；失败 → Note 恒为「找不到文件」。
    Relink(ledger, missingPath, folders, logMiss=false)
      从 ledger.Last(missingPath) 取指纹 → FindMoved → ledger.Relink 成功则
      Log("relink: \"旧\" -> \"新\" (same fingerprint | pages 93% name 71%)")。
      logMiss=false 时找不到不写日志（卡片每拍调也不刷日志）。

    system.io.pipelines 9.0.2 的 lib\net8.0\*.dll 复制到 harness bin 目录（S.T.Json 9 序列化时

  - 另一个 agent 的 `-t:Rebuild` 会把插件 bin 目录清掉，harness 跑到一半就 FileNotFound；
    所以先把插件 dll 复制到 %TEMP%\deck-remap\plugin\ 再跑。

未验证 / 风险
--------------------------------------------------------------------
  - 只用 python-pptx 生成的标准 pptx 验过；WPS/希沃导出的 pptx 若把文字放进图形（p:graphicFrame /
    SmartArt / 备注页），这部分文字读不到，会被当成空页 → Unavailable「没有文字」，不会瞎给页码。
  - 纯图片页、扫描页同理：没有 a:t 就无法对齐，按「可能不准」处理。
  - .ppt（二进制）不支持解析；重关联时这类候选不参与（H23）。
  - 缓存是「第一次看到这个版本时」留的底：如果老师改了课件、又在插件没跑起来（ClassIsland 没开）
    的情况下上了一节课，旧版每页文字没留底，只能给「页码可能不准」。这是设计上的取舍，
    不猜。
  - 本机没有真机跑 ClassIsland（按约定不启动），所以 UI 上的最终文案效果未截图。

需要接线的地方（我没有改 SessionEngine，以下是建议改法）
--------------------------------------------------------------------
1) 留底 + 改名认领 —— Core/SessionEngine.cs `BeginSession`，在 L798 `currentFp = Ledger.Fingerprint(filePath);`
   之后加一行：
       DeckRemap.Remember(ledger.Root, filePath);        // 每份课件每个版本解析一次，约 20~80ms，在引擎线程的 Begin 里
   这样「上次停在第 N 页」对应的旧版每页文字才有据可查。

2) 路径失效时的重关联 —— 同一段的 L804-L822（现在只按「指纹相同」认领改名/挪目录）。
   这里是 BeginSession 已知「当前键在台账里查不到」的位置，接到：
       var moved = DeckRemap.Relink(ledger, filePath, new[] { settings.FindSubjectFolder(subject) }, logMiss: false);
       if (moved.Found) { /* 台账已改到 moved.Path，历史还在；卡片可以用 moved.Path 显示 */ }
   建议把 subject 从 LessonContext 里取；settings 就是现有的 SyncSettings 实例，
   科目文件夹用 SyncSettings.FindSubjectFolder(record.Subject)（找不到会返回 ""，传进去也没关系）。
   找不到时不要动台账（Relink 内部已经保证），保持「找不到文件」。

3) 卡片上的「文件改过，页码已偏移」—— Core/SessionEngine.cs L1500-L1514。
   现在 `st.PreviousTrusted = TrustedFingerprint(r);` 为 false 时只写死一句
   「文件在那之后被改过，页码可能已偏移」，页码仍是旧版第 N 页。
   建议在 `st.PreviousTrusted = TrustedFingerprint(r);` 之后插入（约 L1502 后）：
       if (!st.PreviousTrusted && r != null)
       {
           var remap = DeckRemap.RemapFor(ledger, r, histKey, st.Previous, ledger.Root);
           if (remap.Usable) st.Previous = remap.NewSlide;   // 让 DoJump 跳到对齐后的页
           st.Hint = remap.Note;                             // 可信：对应新版第 M 页；不可信：页码可能不准
       }
   注意 st.Previous 在这之前可能已被 finished 分支置 0（L1497-1498），要放在 finished 判断之后、
   st.Hint 赋值之前。DoJump 用的是 displayed/st.Previous（L1483-1494、L1283），改成对齐后的页码即可，
   不需要动跳转逻辑。
   RemapFor 内部读新版 pptx（一次几十毫秒）+ 查缓存，卡片是 2 秒刷新的，建议按
   （路径 + 指纹）做一次记忆，或只在 !st.PreviousTrusted 时才算 —— 这次的实现里
   RemapFor 每次都会重新 DeckReader.Read 当前文件，如果性能敏感，接线时请在 SessionEngine 侧
   加一层「上次算过的 (path, fp) → RemapResult」缓存。

4) 任务 10 的「卡片显示找不到文件」—— 若 Ui/CardFileList 或 Automation/UnfinishedDecks 里已经有
   File.Exists 判断，可在那里调用同一句 Relink（它很便宜：找不到时不写日志、不改台账；
   唯一开销是扫目录，建议加个「这份课件每 30 秒最多试一次」的节流）。
