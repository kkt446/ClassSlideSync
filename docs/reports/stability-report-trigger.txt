三、程序集反射取证（%TEMP%\auto-trigger\probe，直接加载真实 ClassIsland.Core.dll）
------------------------------------------------------------------------
1) 基类
   ClassIsland.Core.Abstractions.Automation.TriggerBase（abstract : object）
     protected void Trigger()
     protected void TriggerRevert()
     public override Loaded() / UnLoaded()  —— 程序集里是 **abstract**（必须 override）；
                                              api.docs 写成 virtual，是文档滞后。
     object SettingsInternal { get; set; }  —— 访问器 nonpublic
     Workflow AssociatedWorkflow { get; }
     event EventHandler Triggered / TriggeredRevert
        ⚠ **add 访问器是 nonpublic**：外部程序集不能 `trigger.Triggered += ...`（探针里直接写会
          编译报 CS0103「名称不存在」）。但它们是 field-like event，底层存在同名非公开字段，
          反射 GetField("Triggered", Public|NonPublic|Instance).SetValue(实例, 委托) 可以订阅
          （探针实测：订阅后调用 Trigger() ⇒ 收到 1 次；TriggerRevert() ⇒ 收到 1 次）。
          这一点对**插件自己**没影响（插件只调 protected Trigger()，订阅方是宿主），
          只影响自测——harness 就是用反射字段订阅来数"到底触发了几次"。

   ClassIsland.Core.Abstractions.Automation.TriggerBase<T> where T : class（abstract，ctor protected）
     protected T Settings { get; }   —— 内部就是 (T)SettingsInternal
     实测：给基类 SettingsInternal 塞 SetB{Page=42} 后读 TriggerBase<SetB>.Settings，拿到同一个对象。
     实测：SettingsInternal 为 null 时 Settings **返回 null、不抛异常**
           （行动的 ActionBase 在这种情况下抛 ArgumentNullException，触发器宽松一些；
            即便如此，插件代码仍对 Settings 包了 try/catch 兜底）。

2) 注册 API —— 名字就是 AddTrigger，两个重载
   ClassIsland.Core.Extensions.Registry.TriggerRegistryExtensions
     public static IServiceCollection AddTrigger<TTrigger>(this IServiceCollection services)
         where TTrigger : TriggerBase
     public static IServiceCollection AddTrigger<TTrigger, TSettings>(this IServiceCollection services)
         where TTrigger : TriggerBase
         where TSettings : TriggerSettingsControlBase
   实测生成的 ServiceDescriptor：
     AddTrigger<T>()      → ServiceType=TriggerBase,                                   ServiceKey=<TriggerInfo.Id>, Transient
     AddTrigger<T,S>()    → 上面那条 + ServiceType=TriggerSettingsControlBase,         ServiceKey=<同一个 Id>,     Transient
   ⇒ 与 AddAction<TAction, TSettingsControl>() 完全同构：设置控件以同一 Id 注册成 keyed transient。
     宿主按 Id 取触发器实例、按同一 Id 取设置控件实例。

   实测失败模式（对写插件有用）：
     * 重复 Id：抛 InvalidOperationException("此自动化触发器id <id> 已经被占用。")
       抛点 TriggerRegistryExtensions.cs:51（Register 内），AddTrigger<T,S> 在其 :36 调用它。
       Id 去重表是**进程级静态**，换一个 ServiceCollection 也照样拦。
     * 缺 [TriggerInfo]：抛 InvalidOperationException("无法注册自动化触发器 <类型名>，因为此控件有注册信息。")
       （消息是宿主复制粘贴的笔误，实质=缺注册信息特性）。⇒ TriggerInfo 是必需的。

3) 特性 ClassIsland.Core.Attributes.TriggerInfo : Attribute
     ctor(string id, string name, string iconGlyph = "")
     Id / Name / IconGlyph 只读；TriggerType / SettingsControlType 有 nonpublic setter（由 Register 填充）
   ⚠ 与 ActionInfo 不同：**没有 addDefaultToMenu / defaultGroupToMenu 参数**，
     所以触发器没有「分组」概念，插件里那个 AutomationGroups.Plugin = "课件续页" 常量在触发器上用不到
     （触发器会统一进宿主的触发器列表，按 Name 显示）。

4) 设置控件基类（ClassIsland.Core.Abstractions.Controls）
     TriggerSettingsControlBase : Avalonia.Controls.UserControl（abstract，ctor protected）
        public TriggerSettingsControlBase GetInstance(TriggerInfo info, ref object settings)
        protected object SettingsInternal { get; set; }
        protected virtual void OnPropertyChanged(string)
        protected bool SetField<T>(ref T field, T value, string name)
     TriggerSettingsControlBase<T> : TriggerSettingsControlBase（abstract）
        public T Settings { get; }
   ⇒ 不需要实现 ISettingsControl 之类的接口：继承 TriggerSettingsControlBase<T> 就够了，
     宿主打开触发器设置抽屉时按 Id 取控件 → 调 GetInstance → 把 settings 塞进 SettingsInternal。

5) **时序坑（实测，必须遵守）**：DI 工厂不做设置注入。
   new ServiceCollection().AddTrigger<T,S>() → BuildServiceProvider() →
   GetRequiredKeyedService<TriggerBase>(Id).SettingsInternal == null，
   GetRequiredKeyedService<TriggerSettingsControlBase>(Id).SettingsInternal == null。
   ⇒ 注入是宿主后续（Workflow / TriggerSettings.GetInstance）做的。
     插件侧必须在 Settings 为 null 时回落默认值，并且界面不能在构造函数里读 Settings（那时必为 null）。

6) 其它相关类型

     string Id / object Settings / TriggerInfo AssociatedTriggerInfo / TriggerBase TriggerInstance / event Unloading
   IAutomationService
     List<TriggerInfo> RegisteredTriggers（宿主就是用它给触发器列表喂数据，我们的 Id 会出现在这里）

五、实现说明
------------------------------------------------------------------------
文件：Automation\SlidePageTrigger.cs（231 行）
文件：Automation\TriggerSettingsControls.cs（162 行）

1) 设置数据（SlidePageReachedSettings，POCO，公共无参构造 + 两个可读写属性）
     int  Page    = 1      // 讲到第几页，使用时夹到 1-999（不改写用户填的数字）
     bool AnyDeck = false  // false = 只认正在放映的课件；true = 打开着的课件翻到这一页也算

2) 触发器本体
     [TriggerInfo("ClassSlideSync.Plugin.SlidePageReached", "课件讲到第 N 页", "\uE945")]
     public sealed class SlidePageReachedTrigger : TriggerBase<SlidePageReachedSettings>
         const int MinPage = 1, MaxPage = 999;
         const int MaxRemembered = 64;                  // 去重记录上限
         readonly HashSet<string> fired（OrdinalIgnoreCase）+ readonly object gate;
         public int FireCount { get; private set; }     // 真的调过几次 Trigger()，自测用
         public SlideProgress? LastFired { get; private set; }

     override void Loaded()
         Hook()（取 SlideSyncService、订阅 SlideProgressChanged）
         + 立刻用当前快照 Consider 一次
           —— 理由：触发器可能是在课件已经停在第 N 页之后才被加上/重新加载的，
              那时不该等老师再翻一页。
     override void UnLoaded() → Unhook()（必须退订，工作流重新加载时不能挂两份回调）
     public bool Consider(SlideProgress progress)   // 判定一次；public 是为了自测能直接喂快照
         progress == null                          → false
         !DeckOpen || Current <= 0                 → false（没课件 / 这一拍没读到页码）
         !Showing && !AnyDeck                      → false（只是打开着，没在放映）
         Current != TargetPage()                   → false
         fired.Contains(key)                       → false（同一节课同一份课件只触发一次）
         否则 fired.Add(key) → Fire() → true
         整段 try/catch：自动化里抛异常会打断整条工作流，异常只记台账、返回 false。
     void Fire(...)
         FireCount++ / LastFired = 快照 / 记台账 "trigger fire: ..." / 调 protected Trigger()
         **不调 TriggerRevert()**：这是"讲到了"的一次性事件，没有"不再讲到"的对应状态，
         调用 revert 会让宿主把工作流也回滚一次，语义不对。
     int TargetPage() = Math.Clamp(Settings?.Page ?? 1, 1, 999)   // Settings 为 null 时回落 1
     bool AnyDeck()   = Settings?.AnyDeck == true
     SlidePageReachedSettings? TrySettings()  包 try/catch 读 Settings

3) 去重键（同一节课同一份课件只触发一次的实现）
     键 = 课次 + "|" + 课件
     课次：SlideProgress.LessonKey（"科目|节名|节号"，由课表读数拼出）
           为空时退到 SlideProgress.DayKey（yyyy-MM-dd）——没课表时同一天同一份课件也只触发一次，
           第二天再讲同一份课件会重新触发。
     课件：课件完整路径 → 文件名 → "#" + 当前页（三级退让；路径拿不到时宁可放宽也不永不触发）
     ⚠ fired 是**实例字段**不是静态字段：每个工作流有自己的触发器实例，
       两个工作流都配了「第 5 页」时应该各触发一次，不能被彼此吃掉。
     ⚠ 记录超过 64 条直接 Clear()：等于"忘了以前触发过"，最多让同一份课件多触发一次，
       比让集合无限长好（老师一学期几百份课件，正常远到不了 64 条并发活跃记录）。

4) 线程
     SlideProgressChanged 在引擎线程上抛（SlideSyncService.PublishProgress 里同步调用订阅方）。
     Consider 的判重段有 lock(gate)，不会因为并发心跳重复触发（自测 C27 用 20 线程验证）。
     Trigger() 是同步调用（宿主的 Triggered 处理链同步跑完）。

自测里踩到的两个坑（已解决，记录以免下次重踩）：
  * Avalonia 的 TextBox 把 TextChanged 排到 UI 线程的下一次循环，赋值当场不同步触发；
    harness 改完 Text 要 Dispatcher.UIThread.RunJobs() 才等价于"老师真的敲了字"。
    这不影响真机（宿主本来就有 UI 循环），但意味着**设置是异步提交的**，
    紧接着读 Settings 的代码不能假设它已经是最新值（本插件没有这种代码）。
  * Triggered/TriggeredRevert 的 add 访问器是 nonpublic，只能反射塞字段（见第三节第 1 条）。


九、「如果 2.1.0.1 没有触发器」的备选方案（本次**没有采用**，仅备查）
------------------------------------------------------------------------
触发机制存在，所以不需要。若将来某个版本砍掉了触发器，代价最小的替代是：
用现有的规则（AddRule，UnfinishedDeckRule 那套）+ 一个内置定时器轮询「当前页」，
在规则里比较"上次记录的页 != 本次页且 == N"来模拟触发。
代价（也是它不如真触发器的原因）：
  1. 轮询周期本身就是漏触发/重复触发的来源（页翻得快会整页跳过）；
  2. 规则是"条件"，本身没有"触发一次"的语义，得自己维护"已触发"状态（等于把本报告第五节
     的去重逻辑再写一遍，且放在规则里没有工作流实例隔离，多工作流互相吃掉记录）；
  3. 规则 Evaluate 是无状态的纯函数式约定（现有 UnfinishedDeckRule.Evaluate(ledger, now) 就是），
     在里面塞可变状态会破坏这个约定；
  4. 老师看到的界面也不对：需求是"当讲到第 N 页这个事件发生时启动自动化"，
     用规则只能做成"当讲到第 N 页时条件成立"，需要老师自己再配一个"卡片可见性变化"之类的触发。


十、未验证项（真机才能确认的部分，必须如实列出）
------------------------------------------------------------------------
1. **真机自动化界面未截图、未点过**：本环境被明确要求不部署、不启动 ClassIsland，
   所以「触发器列表里能看到『课件讲到第 N 页』、点进去能编辑页码」只有 API 层面的证据
   （A8-A15：注册描述符 + 容器解析 + 控件可构造 + 文本/勾选框事件写回设置），
   没有真实宿主界面的截图。
2. **图标字形 U+E945（Segoe Fluent Icons LightningBolt）**只是从字体映射表里挑的，
   没在真机字体下确认渲染成闪电而不是豆腐块；改 Automation\SlidePageTrigger.cs:56 的 Glyph 即可换。
3. **真实翻页时序**：trigger 依赖 SlideSyncService.PublishProgress 用的 CardState.Current / 引擎快照。
   真机 PowerPoint/WPS 翻页时这两者是否会短暂为 0、跳页时是否漏过目标页，
   以及 WPS 放映窗口识别不到的已知问题上页码是否还更新（旧报告里 WPS 的部分本来就标了未验证），
   都只能在真机复验。触发器本身对此是保守的：Current<=0 一律不触发。
4. **Trigger() 在引擎线程上同步调用时，宿主是否会把它切到 UI 线程**未验证。
   本插件的行动（AutomationOnUi）自己会切线程，第三方行动是否安全取决于宿主；
   如果真机发现某行动在引擎线程上报错，修法是在 Fire() 里改成 Dispatcher.UIThread.Post(Trigger)
   （代价是触发延迟一拍，且自测的同步计数断言要跟着改成等待）。
5. **工作流保存/重载后的 Settings 反序列化**未验证：宿主把 SlidePageReachedSettings 存成 JSON 再读回，
   新增字段时老配置的兼容性由宿主的序列化器决定（我们的两个字段都有默认值，理论上安全）。
6. **多个工作流各配一个「第 N 页」触发器**时各触发一次（实例字段隔离）是设计意图，
   harness 只在单实例上验证过行为，多工作流并发未在真机验证。
7. 去重记录上限 64 条 + 超限 Clear() 的行为已用 70 份课件验证不抛、不影响后续触发，
   但"清空后同一份课件会再触发一次"这个理论副作用没有在真机上构造出真实场景。
