二、API 取证（Mono.Cecil 只读元数据，没有 LoadFrom 反射宿主，避免依赖解析递归）
------------------------------------------------------------------------
为什么要 Cecil：早前用 AppDomain.AssemblyResolve + Assembly.LoadFrom 加载 ClassIsland.Core
会因为卫星程序集（zh-Hans 等）解析递归导致 Stack overflow。Cecil 只读元数据，零副作用。

1) 基类（ClassIsland.Core.dll，namespace ClassIsland.Core.Abstractions.Controls）
     abstract class ComponentBase : Avalonia.Controls.UserControl
         protected ComponentBase()
         object SettingsInternal { get; internal set; }        // 属性本身 public，setter assembly 级
         public virtual void OnMigrated(Guid sourceId, object settings)
     abstract class ComponentBase<T> : ComponentBase
         protected ComponentBase()
         T Settings { get; }
   注意：网上 1.x 文档提的 OnInitialized 在 2.1.0.1 里**不存在**（基类成员只有上面三项），
   所以本组件用 Avalonia 的附加/脱离视觉树回调来订阅、退订。

2) 特性 ClassIsland.Core.Attributes.ComponentInfo : Attribute
     三种 ctor：
         ComponentInfo(string guid, string name, string iconSource, string description = "")
         ComponentInfo(string guid, string name, string description = "")
         ComponentInfo()
     3 参 ctor 的 IL 里是 Guid = Guid.Parse(guid) —— 这就是"Id 必须是真 GUID"的硬依据。
     4 参 ctor 再走 IconSource = IconExpressionHelper.TryParseOrNull(第 3 参)。
     IconExpressionHelper.TryParse：表达式长度 == 1 → new FluentIconSource(expr)；
     否则按 fluent(...) 之类函数语法查表，未命中返回 false。⇒ 单字符字形最省事。
     特性上还有 SettingsType / ComponentType / IsComponentContainer / MigrateSources 等属性，
     其中 ComponentType 由 Register 在运行时回填。

3) 注册扩展 ClassIsland.Core.Extensions.Registry.ComponentRegistryExtensions
     public static IServiceCollection AddComponent<TComponent>(this IServiceCollection services)
     public static IServiceCollection AddComponent<TComponent, TSettings>(this IServiceCollection services)
     internal static ComponentInfo Register(IServiceCollection, Type component, Type settings)
   Register 的 IL 行为：
     - component.GetCustomAttributes(false) 找 [ComponentInfo]，没有就抛
       ArgumentException("无法注册组件，因为这个组件 " + FullName + " 没有注册信息。")
     - ComponentRegistryService.Registered 已有同 Guid → 抛
       ArgumentException("此组件id " + Guid + " 已经被占用。")
       ⇒ 同 Id 重复注册会直接失败；迁移/改名必须换 [MigrateFrom] 而不是复用 Id。
     - services.AddTransient(componentType)（**普通瞬态，走 DI 构造**）
     - info.ComponentType = componentType

4) 实例从哪来（ClassIsland.Services.ComponentsService.GetComponent 的 IL）
     type = isSettings ? info.SettingsType : info.ComponentType;
     if (type == null) return null;
     return Host.Services.GetService(type) as ComponentBase;
   ⇒ 组件由 DI 容器 new，所以**必须有公共无参构造**（也可以改成构造注入，
     但 AddComponent 是 AddTransient，注入什么取决于宿主容器现有注册，这里不冒险）。
   ⇒ 同一个组件设置里可能有多个实例（主界面 + 管理界面预览 + 设置抽屉），
     每个实例独立订阅，所以订阅/退订必须严格配对（见第六节断言）。

5) 隐藏机制（这是本任务最容易踩坑的地方）
   - 宿主侧 ClassIsland.Core.Controls.ComponentPresenter 的可见性判定：
       CheckHideRule():     HideOnRule && HidingRules != null &&
                            RulesetService.IsRulesetSatisfied(HidingRules)
                            → IsVisibleInternal = false，否则 true
       UpdateComponentHidState(): Settings.IsVisible = IsVisibleInternal && !_isAllComponentsHid
   - ComponentSettings.IsVisible 的 setter 是 **internal**（getter public）：
     IL 就是 ldarg.0/ldfld _isVisible/ret，setter 标记 assembly。
     ⇒ 插件**不能**编程设置"按条件隐藏"，宿主那套 HideOnRule + HidingRules 是用户在
       组件设置里自己配的规则集，插件侧无法代填。
   - 插件侧没有 IHideableComponent 之类接口（Core 里全量搜过，没有）。
   - ComponentPresenter.axaml 里有 class:comps-hidden 样式，但它的触发源是 IsVisibleInternal
     （宿主自己的属性），不是组件的 IsVisible。
   ⇒ 插件唯一不越权、且语义正确的做法：组件自身 IsVisible = false。
     Avalonia 的 IsVisible=false 不是"透明"而是**折叠**：不 Measure、不 Arrange、不 Render，
     期望尺寸为 0，ComponentPresenter 的 Border 不会留下和组件一样高的空位。
     （本报告第 七 节把"未在真机上肉眼确认像素级间距"列为未验证项，见那里。）

6) 字体/主题跟随（不起作用就等于没做）
   - MainWindowCustomizableNodeHelper.ApplyStyles(Control, IMainWindowCustomizableNodeSettings) 会往
     control.Resources 里写四个键：
         MainWindowSecondaryFontSize / MainWindowBodyFontSize /
         MainWindowEmphasizedFontSize / MainWindowLargeFontSize
     （若用户关掉了"覆盖字号"，这 4 个键会被 Remove，回落到全局资源 → 组件自动跟随全局，
       这正是我们要的"随主界面字体走"而不是写死字号。）
   - 内置组件确实这么用（Cecil 扫 !XamlIlPopulate 里的 ldstr 证实）：
         ClockComponent → MainWindowEmphasizedFontSize
         CountDownComponent → MainWindowBodyFontSize
         WeatherComponent → MainWindowSecondaryFontSize
         ComponentPresenter（OnMainWindow 时给 Border#ComponentRootBorder 设 TextElement.FontSize）
             → MainWindowBodyFontSize
     TextElement.FontSize 是继承型附加属性，所以组件内部不设字号也会自动继承主界面正文字号。
   - 纯 C# 里用 DynamicResource 的正确姿势（本组件采用）：
         textBlock.Bind(TextBlock.FontSizeProperty, new DynamicResourceExtension("MainWindowEmphasizedFontSize"))
     DynamicResourceExtension 在 Avalonia.Markup.Xaml.dll（Avalonia 11.3.17，Avalonia 主包传递引用，
     不需要额外加 NuGet），实现 IBinding，可直接交给 Bind。
   - 主题色：本组件**不设任何前景色/背景色**，继承宿主 TextElement.Foreground 与
     ComponentPresenter 的 Opacity/BackgroundColor 绑定 → 深色/浅色主题、用户自定义颜色都自动跟随。
     也不设 Margin/Padding/宽度，让组件设置抽屉里的边距/宽度控件真正生效。

     protected override void OnDetachedFromVisualTree(...) → Detach() + base      // 第 231 行

七、未验证项（老实列出来）
------------------------------------------------------------------------
1. **真机像素级效果未验证**（没部署、没启动 ClassIsland）。逻辑与元数据全验过，但"隐藏时
   ComponentPresenter 的 Border 是否还有 1-2 像素的间距"只能靠 Avalonia 折叠语义推断
   （IsVisible=false 不参与布局 ⇒ 期望尺寸 0）。如果用户反馈"角落有个小空档"，那是宿主
   行/组件容器的 Margin，不是组件本身；解法是让用户在组件设置里把该组件边距调 0，或把组件
   放在独立一行——不需要改代码。
2. **字号键的实际取值未验证**：只验证了"DynamicResource 跟随资源变化"，没验证用户把
   "覆盖字号"关掉时回落全局资源的观感。回落路径是宿主 ApplyStyles 里 Remove 键 + 全局默认，
   属于宿主行为。
3. **"只有一个组件实例"这个假设没验**：主界面 + 设置抽屉预览可能各有一个实例，每个都独立
   订阅（本组件按实例订阅、按实例退订，逻辑上安全，但没在真机上数过实例数）。
4. **没有设置控件**：这是刻意的（任务只要显示进度）。如果以后想加"显示成 12/24 还是第 12 页"、
   "是否显示课件名"之类开关，走 AddComponent<T, TSettingsControl>() + 继承
   ComponentBase<TSettings>，本组件的 FormatProgress/ShouldShow 已经是纯函数，改造成本低。
5. **课堂切换/跨天**：进度完全来自 SlideSyncService（它负责课次/课件识别）；组件只做显示，
   没有自己的时间/课表逻辑，所以课次相关行为等同于该服务已有行为，未额外验证。
6. 图标字形 \uE8A5 只验证了"能解析成 IconSource"，没在真机上看过渲染效果；备选 \uE7C3 / \uE9D2。
